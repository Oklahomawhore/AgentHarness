# AgentHarness 当前阶段计划：显式房间上下文

Status: implemented
Date: 2026-08-20

本阶段只完成 context 插件：解决当前房间成员显式发布的哪些文本进入已加入 Agent 的请求。它依赖房间插件，但拥有独立日志、持久化和模型消息来源。

## 范围

每次共享只包含 `roomId`、当前成员 `participantId` 和纯文本。服务验证房间与成员关系后，把记录追加到单 Host 的仅追加 context 日志。它不读取或广播任何参与者的私有 Session 历史，不引入 task、owner、权限、工作分配、总结或协作判断。

Agent 在下一次 `agent/pre-step` 只选择当前仍已加入房间、且其 Session 尚未记录引用的最早 context 记录。一次请求的记录数受配置限制，剩余记录留给后续请求。选中的批次作为带 `development-room-context` 来源的持久用户消息写入 Session，因此恢复后不会重复选择。

context 日志通过独立 storage-domain 包持久化。持久化失败会拒绝共享且不占用序号；冷启动会恢复本节点完整日志，并拒绝外来节点、间隙和相同位置冲突。当前阶段不把 context 记录塞入房间日志，也不扩展房间 WebSocket wire；跨节点 context 复制留给 context 层自己的后续传输。

## 当前阶段验收

- [x] 只有当前房间成员可以显式共享非空、受 UTF-8 字节限制的纯文本。
- [x] 所有接受的共享形成一份无更新、删除、截断或压缩操作的仅追加日志。
- [x] 持久化先于内存发布，失败时日志与下一序号保持不变。
- [x] 当前已加入房间的 Agent 在下一次请求看到最早的未读记录。
- [x] 每个 Session 通过持久来源引用只接收每条记录一次，恢复后也不会重复。
- [x] Agent 离开房间后不再接收该房间之后发布的记录。
- [x] storage-domain 冷启动恢复房间与 context 日志，并对异节点持久化内容 fail-loud。
- [x] 无模型 headless 快照证明共享文本、房间话题、发布者和日志引用进入真实 Agent 请求。

## 本阶段之后

下一阶段才评估共享 agent 插件，候选能力限于基于已进入共享上下文的总结、收尾和协作问题发现。该插件不得反向改变房间日志或 context 日志的基本实体，也不得在没有具体消费方时预先增加字段。回显 UI 仍属于更上层的独立阶段。
