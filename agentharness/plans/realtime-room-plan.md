# AgentHarness 当前阶段计划：本地实时房间网络

Status: implemented
Date: 2026-08-20

本阶段只完成房间插件：解决谁和谁相连。加入、离开和实时更新通过浏览器验收前，不实现后续层。

## 四层架构

1. 房间插件记录连接关系和临时话题，本阶段位于此层。
2. context 插件决定哪些材料进入共享上下文，依赖房间插件。
3. 共享 agent 插件提供总结、收尾和协作问题发现，依赖 context 插件。
4. 回显插件呈现丰富协作信息，可以消费以上全部插件。

## 房间层数据

房间层只保留三类不可变记录：创建房间、参与者加入、参与者离开。所有记录进入同一份仅追加日志；房间目录与成员关系完全从日志派生。

参与者资料只包含稳定 id、人或 agent 类型和显示名；在线心跳是瞬时目录状态。它们都不进入房间日志，能力、活动、任务和 owner 也不属于这一层。在线状态与成员关系彼此独立：下线不会离开房间，离开房间也不会改变在线状态。

mesh 只在已配置的本地节点间复制日志和在线状态，并把加入／离开路由到创建该房间的节点。它不引入登录、主体绑定、访问策略或变更审批。

## 当前阶段验收

- [x] 同一 Host 可以创建多个临时话题房间。
- [x] 本地协作者无需先加入即可看到完整房间目录及后续创建事件。
- [x] 创建房间不会隐式加入任何参与者；界面在创建后显式加入当前协作者。
- [x] 加入和离开幂等，并且只追加真正改变成员关系的记录。
- [x] 创建、加入和离开形成一份无截断的仅追加日志。
- [x] 日志通过 storage-domain 持久化并可在冷启动后重建房间目录。
- [x] 已配置节点通过 WebSocket 复制日志并路由跨节点加入与离开。
- [x] 页面使用不透明底色，只展示协作者、房间目录和成员关系。
- [x] 在实际 Web 页面完成双参与者创建、加入、离开与实时更新验收。
