# Agent Note: 在同一原 Session 中组合获准的工作来源

Status: proposed

[English](2026-10-14-combined-native-work-sources.md) | 中文

## 问题

一个人现有的 Agent 经常在同一回合修改文件、运行检查，再解释结果。[原生采集器](../../../../packages/collaboration/scope-agent-contribution/README.zh.md) 的每个 capture 只能选择工具来源或完整答复来源。选择任一种都会遗漏另一类证据。更换许可、手工发布或为同一个人另建辅助 Agent，增加了[按人类职责协作](../../implemented/process/2026-10-05-collaboration-follows-human-responsibility.zh.md) 本来要消除的协调工作。

## 提案

新增明确版本化的原生组合来源，继续让每个 Session 的本地／远端角色各持有一个 capture。用户在一次申请中选择允许的文件操作、精确前台命令和完整最终答复，逐类查看披露说明。批准绑定完整选择。现有工具和答复许可保持原义，不隐式获得组合许可。

使用一个 grant、capture 身份、sequence、累计样本额度和持久 outbox。保留现有工具结果与最终答复的证据类型、原 provider 观察和持久回合证明。每条样本必须匹配已选择的类别；共享 Task 或声明的角色都不授予执行或披露权限。一次停止、到期或撤权终止该 capture 的全部类别。关联读取许可仍按其现有独立生命周期处理。

为新来源定义明确的新 wire 形式和持久行判别值。旧形式必须拒绝新权限，已提交的 Session 代次保持不变。同步两套 SDK，以及处理该来源的全部解析器、渲染器和证据解码器。保留[报告分配](../../implemented/feature/2026-10-14-source-fair-reported-context.zh.md)、完整字段的精确容量限制，以及明确的 unsupported／omitted 覆盖说明。工具证据不能认证答复；仅因答复更晚，也不能认定它替代较早答复。

首个实现不包含历史初始化、活动 capture 内的类别变更，以及面向多个远端 owner 的并行 capture。保留[完整答复来源证明](../../implemented/feature/2026-10-14-completed-answer-contributions.zh.md)，包括排除受管自动回合。有限自动响应仍单独授权；组合披露不能启用它。这些自动回合的最终答复仍被排除，因此自动接收场景不能证明双向自动答复循环。

## 考虑过的替代方案

**每个 Session 多个 capture。** 现有运行时所有权、队列、outbox 行、读取接纳和自身报告排除，都按每角色一个 capture 处理。多个 capture 扩大生命周期状态，也让用户为同一份工作管理多个许可。在一次批准中组合类别不需要这种复杂度。

**工具工作和解释使用不同的辅助 Session。** 这仅为满足通信系统而改变用户现有的 Agent 安排，不能证明原 Session 之间的协作。

**从文件推断答复，或用现有文件同意覆盖答复。** 工具观察不包含用户完整的解释。答复可能引用私人输入，因此披露它必须由用户单独选择。

## 验收标准

1. 两个既有原生 Session 保留独立分配的本地 Task、历史和工具。一次联合申请及批准选择工具操作、精确命令和最终答复。来源在普通回合中实际执行 Write/Edit、Bash 并给出正常最终答复；原接收者的真实 provider 请求得到三类获准信息，不调用 publish／recall，也不创建辅助 Agent。
2. 后续执行同一命令从成功变为失败。当前失败替代旧成功，独立署名的答复仍可区分。完整证据适配固定 8,000 字节测试额度，不能把遗漏静默当作完整覆盖。
3. 未许可类别、同意前工作、取消或被追加输入的答复、旧授权代次不能进入 capture。一次撤权移除全部当前贡献，拒绝迟到结果，同时保留其他 capture、原本地分配和已记录历史。保存失败时保留有界可重试工作，冷恢复不能恢复披露。
4. 独立自动响应场景使用接收者自己的本地目标和有限额度，观察真实自动请求并验证累计使用。手工发起接收 prompt 不能证明空闲执行。
5. 真实 Loader、TypeScript/Python SDK 与浏览器路径验证同意、持久来源结果、owner 回执及真实接收请求。已提交的历史 JSONL 代次保持原字节；运行中的原 Session 只追加事件，不重建或替换。新增 writer 记录保留旧 oracle。
6. 原生成功只是中间能力，不代表外部会话验收完成。对受支持的外部 CLI，须在已经运行的原 Session 中演示相同生命周期，并记录安装、网络步骤、权限、真实输入和耗时。缺少可靠最终答复来源证明的适配器，必须拒绝该类别，直到明确的适配器设计提供证明。新建 Harness Session 不能替代此项验收。

## 风险

组合许可扩大披露范围，并可能更快消耗共同额度。界面必须展示每个已选类别，说明最终答复可能引用私人材料。共用表示不能证明事实一致、模型理解、所选来源之外的隐私保证或实时网络表现。真实模型和物理设备仍需独立验收。

现有工具来源、完整答复和分配决策继续有效，因为它们的来源证明、权限和表示规则仍然适用。本提案新增一种许可，没有取代这些记录，也不描述已经可用的能力。
