# Agent Note: 协作优先的启动体验

Status: implemented

[English](2026-09-23-agentharness-room-first-onboarding.md) | 中文

## Problem

新安装在用户看到协作产品前就显示模型凭据引导。公开 README 主要描述未来愿景，没有说明当前 Task 流程或展示真实界面。模型不可用时，对话输入区也缺少直接的配置入口。

## Decision

涌现协作中心在启动时展开。用户无需模型密钥即可保存身份、创建 Task 和查看共享上下文。用户点击对话输入区且没有可用提供方时，设置外壳才挂载 DeepSeek 凭据步骤。受阻的输入区保持只读，点击不会发送提示词。既有凭据编辑器通过 credentials 服务保存密钥。

[项目 README](../../../../README.zh.md) 通过两个用户场景介绍协作式上下文工程：前端、后端和算法一起交付一个需求，以及老板和员工共享进展与决策。示例说明各参与者贡献什么、谁可以据此继续工作。进展指主动发布的已完成工作、阻塞和下一步，不暗示自动跟踪完成度。浏览器验收流程的截图辅助展示这些场景。README 和[用户指南](../../../../docs/user/guide/index.zh.md)使用已发布的 npm 引导命令，区分客户端配置、会话连接和上下文确认，并为不同机器提供集群配置链接。README 明确 AgentHarness 及其维护者独立于 DeepSeek，单独链接上游来源说明，避免与产品功能混淆。

## Alternatives considered

在页面加载时弹出凭据对话框会遮住协作产品。创建 Task 不发起模型请求，因此强制先填密钥会增加不必要的依赖。查询参数也可以选择 AgentHarness 启动视图，但浏览器认证会重定向到干净的 URL 并清除查询参数；URL 片段可以保留。

**以泛化的工作空间描述、操作清单或长期愿景开场。** 这些开场让读者自行猜测谁在协作、各自贡献什么、其他人如何使用这些信息。基于角色的场景先说明用户收益，再解释 Fork 与 Merge 机制；更广泛的设计目标由白皮书承载。README 保留安装命令，将详细操作指向用户指南。

## Consequences

首次打开就能看到协作功能。模型对话仍需要工作区和可用模型；用户选择工作区并点击对话输入区后才出现密钥弹窗。如果路由不可用的原因不是缺少 DeepSeek 凭据，就绪检查不会显示误导性的密钥表单，用户仍可从 Models 设置排查。引导声明仍为其他外壳注册，但这条按需路径不会挂载它。

README 展示可用的上下文共享操作，不暗示自动发布、语义冲突解决、代码合并或 Task 审批流程。文档检查验证链接和双语配对；Task 与上下文测试覆盖固定版本、继承发布内容的选择和会话隔离。本次文案调整不增加运行时行为。
