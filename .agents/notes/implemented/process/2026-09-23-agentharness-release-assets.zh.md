# Agent Note：核验公开 Release 附件

状态：已实现

[English](2026-09-23-agentharness-release-assets.md) | 中文

## 问题

首次 tag 工作流的五个平台构建全部成功，便携归档和 npm 启动包也已经发布，但 Release 摘要响应中的附件列表为空。依赖该列表的修复运行尝试再次上传已有文件，收到同名附件错误；独立的 Release 附件接口和公开下载地址证明附件实际存在。

## 决策

tag 工作流比较暂存文件名与独立 Release 附件接口的结果，只上传缺失文件；仍不一致则失败。手动运行入口接收成功的 tag run ID 和稳定版本 tag，下载该 run 的五个平台产物，重新生成 npm 包和校验文件，只上传缺失文件并核验附件名称。手动入口不重新构建运行时，也不创建新版本。

## 考虑过的方案

信任 Release 摘要中嵌入的附件列表会误判为缺失。重新构建五个平台可能生成与成功 run 不同的字节。独立附件接口和修复入口保留已经通过验证的归档，同时能识别真正缺失的下载文件。

## 影响

独立附件接口在重试后仍未展示预期文件时，Release job 会失败。只要成功 run 的产物仍在保留期内，维护者就能修复不完整的公开 Release，不覆盖已有文件。npm 发布 job 在仓库认证和开关配置完成前仍保持关闭。
