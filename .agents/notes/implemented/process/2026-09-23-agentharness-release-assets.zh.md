# Agent Note：核验公开 Release 附件

状态：已实现

[English](2026-09-23-agentharness-release-assets.md) | 中文

## 问题

首次 tag 工作流的五个平台构建全部成功，Release job 也显示成功，但公开后的 Release 没有可下载附件。上传命令的退出状态不能证明公开附件列表中确实有便携归档和 npm 启动包。

## 决策

tag 工作流比较暂存文件名与公开后的附件列表；两者不一致时向已公开的 Release 重试上传，仍不一致则失败。手动运行入口接收成功的 tag run ID 和稳定版本 tag，下载该 run 的五个平台产物，重新生成 npm 包和校验文件，上传到已有 Release 并核验附件名称。手动入口不重新构建运行时，也不创建新版本。

## 考虑过的方案

重跑原 tag 工作流会对已公开的 Release 提前返回。重新构建五个平台可能生成与成功 run 不同的字节。独立修复入口保留已经通过验证的归档，并把下载附件缺失作为明确失败处理。

## 影响

GitHub 重试后仍未展示预期附件时，Release job 会失败。只要成功 run 的产物仍在保留期内，维护者就能修复不完整的公开 Release。npm 发布 job 在仓库认证和开关配置完成前仍保持关闭。
