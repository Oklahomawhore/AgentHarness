# Agent Note: 协作评价保留既有的人类职责

Status: implemented

[English](2026-10-05-collaboration-follows-human-responsibility.md) | 中文

## 问题

自动推进的共享 Task 可能被当作多个 Agent 天然优于单 Agent 的证据。这种表述会把独立拥有的工作替换成人为任务拆分，并诱导系统默默汇集凭据或指派其他参与者。它也掩盖了参与者真正想消除的成本：持续维护彼此相关的上下文。

## 决策

[白皮书](../../../../docs/whitepaper.zh.md#human-responsibility)维护产品原则与评价标准。AgentHarness 协作连接由具有既有职责和权限的人选择的 Session。可替换上下文 backend 为这些接收者准备证据，不选择全局 Agent 层级。参与者自己的子 Agent 和工作流仍是其运行时内部的实现选择。

自动响应是本人针对本地选择的目标和有限额度，许可 Agent 对共享变化采取行动。Task 所有者填写的职责为支持它的 backend 提供上下文整理依据，不授权另一个人的执行。默认 Text backend 不按职责做语义筛选。[原生控件](../architecture/2026-10-03-native-scope-session-controls.zh.md)继续维护运行时权限机制；[联合加入](../feature/2026-10-04-native-joint-join.zh.md)继续维护独立的读取与贡献同意。职责字符串不是工具 ACL，贡献根目录约束报告而非执行。

各协调基线的评价保持人的所有权、工作区、凭据和可用工具不变，测量上下文维护负担、当前事实采用、无效唤醒、产物质量和成本。把全部凭据合并到一个 Agent 属于另一种场景。受控响应证明机制，不证明真实模型遵守职责或双人可用性。

## 考虑过的替代方案

**以 Agent 数量或全局 Task 完成为主要结果。** 即使这些指标改善，产品仍可能转移职责或访问权，未证明原参与者的协调工作减少。

**把职责当成已强制执行的权限。** 提示文本和 backend 相关性可以引导行为，但拒绝操作由实际工具准入和访问控制负责。产品文案必须说明每项主张由什么机制支持。

**禁止参与者内部委派。** 这会替参与者规定运行时架构，也不能证明协作各方具有独立所有权。

## 影响

本决策修改产品定位与评价标准，不修改运行时授权或持久 Session 数据。现有权限、恢复和接入记录分别维护不同实现决定，仍保持有效。[协作优先接入](2026-09-23-agentharness-room-first-onboarding.zh.md)继续维护实际入口流程。文档校验检查公开原则；行为主张仍需相应运行时测试与模型评价支持。
