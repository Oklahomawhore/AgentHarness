# Agent Note: 完整运行独立验证门禁

Status: implemented

[English](2026-10-26-complete-independent-gates.md) | 中文

## 问题

门禁级快速失败会中断独立验证以节省 runner 时间。它的进程树取消逻辑跨异步观测缓存数字 PID 和进程组 id。进程可能在升级终止信号前退出并复用 id，因此缓存无法确定后续信号会影响哪个进程。带创建身份的 PID 清单仍不能识别未被观测的进程组生命周期。历史[快速失败决策](../../archived/process/2026-08-27-gate-runner-fail-fast.md)用完整诊断换取这套额外取消机制。

## 决策

[门禁调度器](../../../../scripts/run-gates.ts)在配置的并发上限内完整运行每项独立检查。`needs` 前置失败仍跳过依赖方；`after` 等待结算；`allowFailure` 保留独立的聚合判定规则。子进程退出、信号、启动错误和可归因输出保留各自的常规观测。不削减验证清单、覆盖率阈值、worker 上限或 job 期限。

调度器没有快速失败选项、执行器 AbortSignal、分离子进程启动、PID 采样或进程树终止。它观测直接进程完成，不承诺后代进程静止。测试和应用仍负责自身资源；产品的子进程及终端 provider 保留各自的释放要求。

当前 [CI 工作流](../../../../.github/workflows/ci.yml)使用标准托管 job，没有门禁级取消标志。GitHub 说明了[全新托管机器](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners)和[工作流取消](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-cancellation)；这些 job 级机制不提供兄弟检查运行期间的逐门禁清理。本地前台中断的传递不覆盖只发给协调器的信号，也不覆盖已脱离的后代。

## 验证

[调度器测试](../../../../scripts/run-gates.spec.ts)保留图校验、依赖顺序、worker 上限、流式输出及真实子进程结果。被屏障保持的兄弟项和排队独立检查会在先前失败后继续运行。真实 CLI 夹具让第一项叶子检查失败，并验证其余独立项全部执行，同时聚合仍以失败退出。[工作流测试](../../../../scripts/ci-workflow.spec.ts)拒绝重新引入取消标志。

## 曾考虑的替代方案

**保留另一套门禁专属进程控制器。** 拒绝，因为仅检查 PID 身份无法在组长退出后保留进程组身份；再实现一个持久所有者会重复产品生命周期基础设施。

**复用当前子进程 provider。** Linux scope 和 Windows Job 提供更强的所有权，但 macOS 及原生能力不可用时的 fallback 仍使用数字进程组。直接替换既不保留分离后代清理，也不解决 id 复用，还会向验证工具引入插件与原生启动依赖。

**关闭 CI 标志但保留可用的取消能力。** 拒绝，因为这会保留不安全的可选实现及无法成立的承诺。

**失败后仅停止启动排队的独立检查。** 拒绝，因为它会扣留有用的验证证据，并增加没有当前消费方的策略。

## 后果

失败运行可能消耗更多 runner 时间，因为独立检查会完成；并发和 job 期限仍有界。调度器放弃首次失败时取消兄弟检查，以及可选的宿主中断进程树排空。移除的进程创建身份控制用例记录已退役能力的缺陷，并不证明完整运行调度器具有等价的后代清理能力。未来重新引入门禁级取消前，需要每个受支持平台都有持久范围所有者，并证明中断与后代静止。
