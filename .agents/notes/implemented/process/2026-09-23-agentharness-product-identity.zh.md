# Agent Note：统一发行与协作中的产品标识

Status: implemented

[English](2026-09-23-agentharness-product-identity.md) | 中文

## 问题

仓库、公开安装包、运行命令、MCP 注册项、工具名、本地数据目录和文档使用了不同的产品标识。只修改展示名称会让可复制的说明与安装后的行为不一致。

## 决定

AgentHarness 是展示名与 GitHub 仓库名；`agentharness` 是 npm 包、安装命令、MCP 注册名和默认数据目录。部署设置使用 `AGENTHARNESS_*`，协作 MCP 工具使用 `agentharness_task_*`。公开引导包、便携运行时、浏览器指引、示例、生成目录和双语文档同时采用这些标识。不注册旧协议名的别名。

本地协作状态使用新目录和凭据名，不会隐式导入已有安装。上游 DeepSeek Harness 包保留原有包名及其常规 Harness home。

## 考虑过的替代方案

只修改仓库和 README，会让首次使用界面继续显示不同的命令与 MCP 术语。为此前的每个标识保留隐藏别名，会在缺少受支持迁移方案的情况下扩大安装器与协议。产品选择明确的兼容性变化，并保持新标识内部一致。

## 结果

从早期预览版升级的用户需要先停止原运行时，再重新配置 Agent Session。原有协作凭据与 Task 数据留在原位置；新安装器不会删除它们。新安装从独立的协作状态开始。发行烟测覆盖安装命令、浏览器和 MCP bridge；文档检查验证当前链接与双语页面。
