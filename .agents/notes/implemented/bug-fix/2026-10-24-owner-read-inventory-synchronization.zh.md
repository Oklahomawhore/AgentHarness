# Agent Note: 所有者控件共享持久化读取授权通知

Status: implemented

[English](2026-10-24-owner-read-inventory-synchronization.md) | 中文

## Problem

成员卡和独立读取控件通过不同清单描述同一份读取权限。仅刷新发起操作的面板，会在批准后隐藏撤销入口，或在撤销后仍显示成员读取有效。本地回调无法观察另一个浏览器的操作，也无法观察恢复审批后才提交的读取授权。

## Decision

[Scope access](../../../../packages/collaboration/scope-access/README.zh.md)在读取授权持久化创建或撤销后发送既有授权变化通知，包括恢复已保存的联合审批。写入失败或授权未变时不发送新通知。通知只表示清单失效；经过认证的查询仍是权威。

[Client 插件](../../../../packages/client/ui-emergence-center/README.zh.md)通过既有 contribution directory 持有独立读取清单。同一 Host 通知同时使这份清单和相关 Task 的成员清单失效。框架生成的 hooks 向组件提供已确认数据；表单输入和显示暂态仍由组件持有。目录代际拒绝陈旧响应，面板关闭后修改仍保留待定状态，连接重置则读取新基线。

权限确认刷新进行时，分页保持禁用。加载下一页不能替换该刷新并保留前一页的过期权限。

目录分别保留不确定的操作结果和状态读取失败。自动读取恢复会清除自身的读取错误，并保留丢失操作回包的警告，即使其间确认读取失败；显式重新读取或后续操作会清除该警告。显式重新读取即使复用正在进行的自动读取，也会保留这一确认语义，不另发请求。恢复提示按映射后的消息键分类，而非原始网关错误码：未知结果的建议等待操作结算、刷新可用后显示，明确拒绝则可在确认期间保持可见。

Task 上下文确认会更新任务进度，而不会刷新此前查看过的每个 Native 本地许可；只有绑定和清除会改变其分配身份。这类事件使匹配参与者及身份尚未确定的记录失效；已确认无关的 Session 保留现有观察。

## Alternatives considered

**本地点击后刷新相邻面板。** 这种方式遗漏其他浏览器和已保存审批的恢复，也让一个组件负责另一个组件的权限查询。

**传入成员清单版本以触发另一个组件读取。** 这仍为异步读取状态保留两个所有者，并把读取清单与成员卡的显示生命周期耦合。

**轮询清单。** 轮询增加持续查询，仍然留下陈旧窗口。既有的已提交授权通知能够指出清单何时需要重新确认。

## Consequences

读取和贡献仍使用独立权限，其显示同步更新。清单确认失败会保留上次观察并禁用修改；重试仅查询权限，不重复先前修改。Claude 接收变化在等待清单确认前刷新 Session 目录。通知不会重放，因此重新连接仍需重新读取；显示状态不证明上下文送达或当前 peer 可达。

同页测试挂载生产插件、slot renderer 和两个控件，覆盖批准、独立及其他浏览器撤销，以及清单确认失败时的 Session 刷新。Host 测试确认持久化写入时的通知顺序，包括恢复联合读取授权。这些观察不会改变或替代 Host 权限执行。
