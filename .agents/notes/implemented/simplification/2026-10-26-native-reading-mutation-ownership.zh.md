# Agent Note：原生读取变更只有一个结算所有者

Status: implemented

[English](2026-10-26-native-reading-mutation-ownership.md) | 中文

## Problem

读取操作可能在面板断线或卸载后提交。连接重置时释放锁会允许重复操作，发布旧响应则可能覆盖新的观察。如果只有该操作能够释放锁，比较令牌不会增加保护。

## Decision

[原生读取存储](../../../../packages/client/ui-emergence-center/src/client/native-scopes.ts) 使用一个布尔值排除重叠变更。它在通知订阅者前加锁，并在连接重置和最后一个订阅者退出后保留锁。只有已发送操作的结算能够释放它，释放先于通知剩余订阅者。因此，重入订阅者与普通调用者遵循相同的互斥规则。

连接代际独立拒绝旧变更结果。活跃订阅检查阻止卸载后的界面更新和恢复读取。状态读取保留令牌身份，因为重置可以用新读取替换尚未结束的读取。

## Alternatives considered

**在结算时比较变更令牌。** 持锁期间没有其他操作能够替换该令牌，重置和取消订阅也会保留锁。身份比较重复了互斥规则，没有比较独立所有者。

**在重置或取消订阅时释放锁。** Host 仍可能提交该请求。第二个操作会与尚未确认的写入重叠；重新连接必须在结算后读取当前状态，不能重试该写入。

## Consequences

存储保持同一时刻只有一个请求，无需变更身份或额外控制器。测试覆盖重置、卸载后结算、重新挂载、共享订阅者，以及不重复变更的恢复。权限、状态读取身份、连接检查和 Host 权限仍是独立要求。
