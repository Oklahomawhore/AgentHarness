# Agent Note: 受控原生 Scope 评测

Status: implemented

[English](2026-10-03-scope-native-evaluation.md) | 中文
## 问题

产物检查器可以识别已知客户端行为，却不能证明接收 Session 实际完成文件工作。执行未经审核的产物还会带来两个独立风险：访问目标项目之外的资源，以及伪造判分报告。仅仅分开文件无法解决其中任何一个风险。

## 决策

四个命名 `dsh` profile 分别运行来源、Task owner、前端 Session 和 QA Session。经过审核的工具调用程序使用普通生产贡献 hooks 和被动 scope 消费。共同工具返回屏障分隔来源准入与接收者继续执行。记录的来源收据、owner 事件、实际请求和恢复的 Session 前缀，证明同一项已准入更新在文件工作继续之前进入下一次请求。这是运行时校准，不是模型推理。

[原生命令](../../../../scripts/scope-evaluation/native-cli.ts)串联 F1 的无共享与接收者事实运行，在产物封存之后进行隐藏 Docker 判分，并包含取消对照。记录的身份覆盖评测源码和显式解析的已构建入口，不覆盖完整依赖图。两个对照组使用相同的已审核程序，因此这些证据与真实模型对比保持独立。

[评测 owner](../../../../scripts/scope-evaluation/README.zh.md)保留精确受控源码注册表，同时允许判分器在 Docker 中执行已登记程序。父进程独立于 IPC 代理拥有容器身份、实际检查的限制、有界清理和删除证据。隐藏判分器不在挂载的角色目录内。

Docker 执行不能证明报告来源可信。候选测试与 Node 测试运行器共用报告进程，因此任意产物仍在分配执行资源之前被拒绝。检查器只有具备独立可信报告器和狭窄操作通道之后，才能宣称抵御候选程序伪造报告。

## 验证

[原生检查](../../../../scripts/scope-evaluation/native-run.spec.ts)覆盖 F1 的共享事实与无共享，以及工具返回之前的取消。[Docker 检查](../../../../scripts/scope-evaluation/docker-execution.spec.ts)覆盖实际限制、判定文件写入、终止状态、时限和清理。[判分器检查](../../../../scripts/scope-evaluation/oracle.spec.ts)保留两种执行模式分配资源之前的受控注册表拒绝。

## 考虑过的替代方案

**把目录或 Node 权限检查当作操作系统隔离。** 它们不能为未经审核的可执行产物提供所需隔离。Docker 提供独立执行环境，但不改变检查器接受哪些源码。

**容器可用后立即开放任意产物判分。** 执行隔离不能阻止测试在自己的报告进程里伪造消息。受控注册表避免把这部分保护描述成可抵御恶意程序的判分系统。

**在执行 Session 之前建立通用防作弊框架。** 这会扩大检查器，却不能证明协作链路。受控限制允许有限的运行时校准，并明确保留结果含义的限制。

## 后果

检查器可以检查并保留已登记案例的执行限制与清理证据。它不能接受任意模型生成的测试，也不能把受控响应当作模型试验。模型推理、质量对比和成本收益测量仍需单独证据；受控执行记录零次模型试验，模型用量与费用未知。
