# Agent Note: 混合上下文证据与产物校准

Status: implemented

[English](2026-10-08-mixed-context-artifact-calibration.md) | 中文

## Problem

一次请求可能遗漏纠正，但其 Session 已从先前轮次知道该纠正。此时只给最终产物评分，无法判断混合输入是否提供有用证据。选中来源列表也不能证明接收者完成了自己的职责或理解了报告的命令失败。

## Decision

独立的[混合工作协议](../../../../scripts/scope-evaluation/mixed-study/README.zh.md)保留原接收 Session 与本地 Task，在下一次工作机会前接纳已纠正策略、变化后的命令结果及无关文档。它不提供中间纠正请求，也不删除历史。N、reported 与 semantic 获得相同工作机会和固定完整上下文额度。旧文本与连续性协议保留各自身份。

父进程独立评分已封存的客户端策略、QA 用例及验证观察。已有证据描述准确性与当前来源可用性是两个独立结果：没有证据时可以声明不可用，但不算完成当前工作。由 seed 派生的来源字段、初始项目和行为参考共用一个定义；隐藏检查不进入接收者项目或受控回复。

普通校准回复只消费实际请求消息与公开项目数据，不接收条件标签或 oracle。受控摘要有意识别注册的策略报告。来源操作、文件产物、采集归属和从持久化事件重建模型消息在独立 Loader 组合中使用生产实现。

## Alternatives considered

**给既有 initial/corrected/mixed 序列评分。** 其中间纠正请求可能在容量遗漏前提供最终答案，掩盖本对照想测量的影响。

**为注册文档调整 reported 选择。** 按路径、角色名或失败码排序不能建立通用职责相关性。实验记录默认后端的实际覆盖。

**把安全不可用或受控正确产物计作产品收益。** 准确表示无证据是有用的安全结果，但没有提供当前事实。脚本回复校准检查器和投递路径，不能证明真实模型任务改进。

## Consequences

本校准无需消耗模型账户，即可揭示实际输入缺失并拒绝陈旧、格式错误或校验不符的产物。它保留完整来源／接收者隔离，不引入按任务拆解的工作 Agent 或新产品权限。它不证明真实模型对照、任意并发、物理设备可用性或语义质量；这些仍是独立的实证要求。
