# Agent Note: Mixed context evidence and artifact calibration

Status: implemented

English | [中文](2026-10-08-mixed-context-artifact-calibration.zh.md)

## Problem

A request can omit a correction while its Session already knows that correction from an earlier turn. Grading only the final artifact then cannot determine whether the mixed input supplied useful evidence. A selected source list also does not prove that a receiver completed its own responsibility or interpreted a reported command failure.

## Decision

The separate [mixed-work protocol](../../../../scripts/scope-evaluation/mixed-study/README.md) retains original receiving Sessions and local Tasks, then admits corrected policy, changed command outcome and unrelated documentation before the next work opportunity. It supplies no intermediate corrected request and removes no history. N, reported and semantic receive the same work opportunity and fixed complete context allowance. Earlier text and continuity protocols retain their own identities.

The parent grades independently sealed client policy, QA cases and verification observations. Available-evidence accuracy and current-source availability are separate results: unavailable evidence permits an unavailable declaration but does not count as completed current work. Seeded source fields, initial projects and behavior references share one definition; hidden checks remain outside recipient projects and controlled responses.

Ordinary calibration responses consume actual request messages and public project data without a condition label or oracle. A controlled summary deliberately selects the registered policy reports. Source operations, file artifacts, captured provenance and model-message reconstruction from persisted events use production implementations. Loader calibration and five named `dsh` Hosts with TCP/Noise provide separate execution checks.

The named-profile driver owns independent scope, policy-source, documentation-source and two recipient processes. Ordinary HTTP-provider reservations are cumulative across initial and mixed work; leaving requires no model turn. Runtime or accounting failure stops later work, while an unsuccessful artifact grade remains a completed observation. Loopback SSE responses consume only actual HTTP message text and public projects, keeping the parent observer and artifact grader independent. This permits transport and lifecycle calibration without substituting scripted success for live inference.

Semantic delivery reuses exact source and authorization identities in mandatory evidence and counts superseded publications per Task revision while retaining complete audit metadata. Native acceptance holds the complete managed allowance at 8,000 bytes, retains both policy quotes and full command observations, and requires both semantic recipients to complete HTTP work and pass independent policy, QA and current-verification grading. N and reported retain their actual business failures without stopping the comparison. The representation changes no owner responsibility, local Task, scope permission, tool or history.

A separate legal oversized-summary control preserves capacity rejection: the first mixed request is persisted with withdrawn context but receives no ordinary HTTP dispatch. The check requires the exact projection-budget error, retained partial artifacts and summary audit, and completed Host cleanup. Controlled responses establish these delivery and failure checks; they do not establish live-model quality or collaboration benefit.

## Alternatives considered

**Grade the existing initial/corrected/mixed sequence.** Its intermediate corrected request can supply the final answer before capacity loss, obscuring the effect this comparison intends to measure.

**Tune reported selection for the registered documents.** Path, role-name or failure-code priorities do not establish general responsibility relevance. The experiment records the default backend's actual coverage.

**Count safe unavailable or controlled correct artifacts as product benefit.** Accurate ignorance is a useful safety result, but it supplies no current fact. Scripted responses calibrate the checker and delivery path; they cannot establish real-model task improvement.

## Consequences

The calibration can expose missing actual inputs and reject stale, malformed or corrupt artifacts without charging a model account. It preserves the full source/recipient separation and does not introduce task-decomposition workers or new product permissions. It does not establish a live comparison, arbitrary concurrency, physical-device usability or semantic quality; those remain separate empirical requirements.
