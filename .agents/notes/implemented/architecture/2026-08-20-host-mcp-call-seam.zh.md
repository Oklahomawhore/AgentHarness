# Agent Note：宿主 MCP 调用使用服务接缝，而非 ToolRuntime

状态：已实现

[English](2026-08-20-host-mcp-call-seam.md) | 中文

## 问题

产品插件需要在 Agent 开始工作前，通过现有 MCP 服务器获取企业证据。原有 MCP 客户端只通过 `ctx.tools` 暴露远程工具，而该接口服务于模型工具执行，会应用展示选择、模型调用审批、任务支持拒绝和会话渲染。可信宿主消费者复用这条路径，会继承只适用于模型请求的行为，并可能在执行自身证据策略前丢失非文本 MCP 内容。让每个证据插件重新实现 MCP 传输，又会重复连接、校验、超时、取消、认证和重连逻辑。

## 决策

新增 `@deepseek-ai/dsh-mcp`，作为宿主侧 MCP 工具调用的传输无关服务定义。传输提供者在 `ctx.mcp` 注册一个精确的已连接服务器世代；消费者使用服务器原始工具名、JSON 参数和调用方取消信号发起调用。服务返回完整 JSON 内容块及可选结构化内容，不注册模型 schema、不请求审批、不渲染结果，也不追加会话事件。

`@deepseek-ai/dsh-mcp-client` 同时担任默认服务提供者和现有模型工具桥接。连接与发现成功后，它把同一个客户端世代发布到 `ctx.mcp`，并把已发现定义注册到 `ctx.tools`。断开时先移除宿主直接调用路由，再关闭该世代。最后一个已知模型工具定义维持原有中断行为，避免重连期间模型提示 schema 抖动；只有恢复后的世代会重新发布。

基础 bundle 挂载服务定义，MCP 传输仍由可选组合提供。消费者依赖 `@deepseek-ai/dsh-mcp`，而不是具体客户端实现。任何返回证据在进入模型前，都由消费者负责选择、限制和记录。

## 结果

后台索引器和证据提供者能够复用同一个受监管 MCP 传输，而不进入模型执行。直接调用会在配置服务器断开时明确失败，继承传输提供者的超时和认证，并保留 JSON 协议内容供消费者校验。注册表只存在于当前进程，只包含可调用世代。当前接口仅覆盖 `tools/call`；资源、提示词、发现元数据、MCP 任务模式执行和 sampling 均延后。

模型可见路径保持不变。`ctx.tools` 继续执行任务支持约束，并产生现有 Native 文本投影。`ctx.mcp` 不执行这些模型专属规则，因此宿主消费者只能直接调用适合普通 `tools/call` 响应的工具。

## 已考虑的替代方案

- **宿主插件调用 `ctx.tools.execute()`**——把产品检索耦合到模型审批和展示行为，并可能在消费者校验前丢失协议内容。
- **从 `mcp-client` 暴露 MCP SDK 客户端**——让消费者依赖单一传输实现，并泄漏连接世代所有权。
- **每个消费者单独建立 MCP 连接**——重复子进程、凭据、重连循环和协议校验，还会让插件间生命周期状态不一致。
