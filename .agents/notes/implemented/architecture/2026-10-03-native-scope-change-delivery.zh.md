# Agent Note：原生 scope 变化投递与有界空闲轮次

Status: implemented

[English](2026-10-03-native-scope-change-delivery.md) | 中文

## 问题

具有独立上下文的原生 Agent 需要在协作者改变 Root Task 时获得当前授权的事实。要求 recall 调用会遗漏 Agent 不知道应当查询的事实。为每个网络通知启动轮次可能消耗无界工作、重新唤醒已取消输入，或把旧投影误当作当前权限。

## 决策

[Scope access](../../../../packages/collaboration/scope-access/README.zh.md) 在独立读取之外提供经过认证的有界 `waitForChange` 操作。不透明游标覆盖 owner、grant 和接收方代际、Task revision，以及 backend identity/configuration。游标匹配时等待变化直至配置的截止时间；未提供游标时在线校准。通知不含事实。游标不是授权租约、采用回执或启动模型请求的许可。

等待拥有独立的取消和最新等待所有权，不会覆盖读取。显式等待容量低于传输请求容量，等待截止时间低于 access 和 transport 截止时间。接收方等待时仍为普通读取和管理保留容量。撤销、过期、本地退出、owner 不可用和等待取消保持不同结果。backend identity 变化可以使游标失效，但不声称底层 Task 事实变化。

[原生 scope 上下文](../../../../packages/collaboration/scope-agent-context/README.zh.md) 通过经过认证的本地管理，将一个已经运行的普通 Session 绑定到独立读取订阅。已有本地分配需要明确的[组合接收同意](../feature/2026-10-07-retain-local-task-during-joint-receiving.zh.md)；职责是路由信息，不是 ACL。没有自动策略的绑定仅开启请求时读取。本地自动策略提供目标、全生命周期绝对启动次数上限、每轮步骤上限和最小间隔。远端来源文本不能授予此许可。

忙碌时的变化把绑定标记为待更新，不加入输入或强迫下一步。在自然 pre-step，consumer 独立在线读取，并在采用前检查当前 Agent、绑定、取消、终态和完整 UTF-8 文本上限。获得许可的空闲绑定合并通知，同一时刻仅拥有一次预取；之后短 Agent maintenance 活动预留一单位预算，并排入一条本地目标触发消息。获准的 pre-step 再次读取，不把预取当作离线授权租约。更新变化不会使原本授权有效的捕获投影失效而饿死投递，而是保留给后续请求处理。 替换或结束 binding 会同步中止其捕获的 watch signal；每次 await 后检查该 signal，也会阻止旧 wait 清除替换后的 watch。本地失效处理携带调用方已选中的本地 binding，并在延后撤回前复核其身份。

空闲撤回在取得 Agent maintenance 所有权后才设置接收方维护标志。若另一个活动占用 Agent，撤回由下一次自然准入处理，不中断订阅清理。它既不取消该活动，也不保留错误的维护声明。自动启动也在设置维护标志前取得 maintenance；占用冲突保留许可和预算，已有待更新调度无需再次恢复命令即可继续。

Session 事件持久保存当前绑定、策略、累计预留次数和待启动 identity。证据投影为冷读取方独立校验请求预留及抑制基线，在线 Agent 的历史校验不能代替它。相同的待启动状态记录保留原预留；改变启动身份、绑定、目标或启用状态会使该预留失效。投影也归约持久化的 `turn/end` 事件，以清除待启动记录，并在轮次未正常完成后暂停已启用策略。这避免从 post-commit 通知追加 Session 事件，因为该处禁止重入 append。已有显式暂停原因保持不变。取消、退出、重新绑定和重启不会退还预留次数，重放拒绝下降的计数。恢复的绑定在显式续许之前保持被动或暂停；恢复 Session 不会重放待执行的自动工作。

Task 与 scope 消费者将精确上下文记录为 user-role 消息，附带来源与权限元数据。首次采用通过 Loop 正常消息批次进入受保护的 system head 之后。上下文变化时用空插件消息清除自有可见节点，再将精确的当前快照追加到此前工作之后。Session 派生省略空 user 节点，因此请求中每个已选来源仅保留一份当前上下文，日志仍保留每个来源事件及替换链接。拒绝或不可用状态按相同顺序追加撤回通知。活跃与分离的 Session 使用同一替换操作，因此冷会话退出无需构造 Agent。自动提醒只携带已授权目标。这些操作不会擦除普通消息引用的事实，也不能证明模型遗忘了先前输入。

被动 Task 消费者在上下文准备失败时恢复尚未提交的输入，并继续报告错误。Loop 已在准入前领取这些输入；重试由新的明确用户续步发起。Task 服务同步提交绑定及其保留的绑定事件；消费者信任该投影。Cordis 在中止准入生命周期之前移除消费者的事件监听器，请求准入也会在确认接收之前检查取消状态。 原生状态、被动接收及本地采集共用 Task 服务按持久顺序确定的最后保留 task-bound 绑定，不依赖时钟或绑定名称。精确本地读取核对所请求的绑定，而非第一个匹配的参与者。保留事件的选择还要求当前绑定属于所请求的参与者；另一参与者复用已清除的绑定 ID 不会暴露其 Task。选中另一个绑定会结束旧本地采集，不续许原有同意。 Task 注入器先检查自身取消，再返回委托的拒绝，因此 Scope 与 Task 同时卸载时，只要原 Agent 请求仍存活，就保留普通 claim。原生取消并丢弃 inbox 输入时不执行恢复。

maintenance 中的取消会同步暂停本地自动许可，并且只删除自有触发消息。消费者在停止自身自动轮次时，会在重新排入输入或发出取消通知前公布既有的空闲结算 Promise。重入的替换许可等待该结算，确保旧轮次的收尾不会暂停替换许可。监听持续到返回的 maintenance promise 结算。Loop 取消会清除原有唤醒标记，同时按请求保留 Inbox 数据；在重入取消之前开始的 send 不能恢复该标记，之后明确发生的 send 仍可唤醒新工作。空闲网络预取时没有可取消的 Agent 活动，因此 `scopeAgentContext.pause` 是整个策略的停止操作。拒绝自动触发消息不会丢弃同批已领取的用户或插件工作。公开的 `agent/inbox/claimed` 事件在任何 pre-step listener 追加上下文之前提供输入 identity 和轮次。这些记录决定是否存在独立授权的工作，而不是可变的 waterfall payload 或派生上下文；每个 pre-step 消耗对应记录，轮次完成或卸载清除残留。 替换许可只等待完全停稳，因此已完成的结算不需要单独的清理状态。

自动轮次的所有权从匹配的 Inbox 领取事件开始，早于其他 pre-step 监听器暂停轮次。 接收器只关联所注入注册表中精确匹配的存活 Agent。分发结算还核对请求标记中的精确 Session 对象，因为隔离注册表可以复用 ID，嵌套的外部请求也可能继承原注册表的异步发起者。即使准入监听器尚未开始，卸载 Scope 也会取消该活动。已捕获但尚未开始的监听器在卸载后继续委托。已经在 Scope 内准备的普通请求在卸载时被拒绝，尚未提交的领取输入仍被保留；已经获准的模型请求可以完成，但不会继续记录 Scope 证据。 在注册项移除后重入注册另一个存活 Agent 时，会先结束原接收器，再完成先前的释放通知。

自动激活在定时回调开始时检查许可：旧定时器可能在已排队的普通轮次之间、尚未发出 idle 通知时触发。激活和绑定的取消会使异步准备失效；只有一个激活会预留生命周期额度。原生 maintenance 同步领取活动并调用任务函数，预留则保留最新状态，包括路由变更。 恢复操作在任何调度写入前比较非空的预期绑定。已退出的 Session 会拒绝该陈旧身份，不修改日志。

监听得到终态结果时，会同步暂停许可并取消尚未预留额度的激活准备。普通准入不共享该激活信号：它保留独立用户工作，并将已观察到的终态应用于迟到的读取结果。

处于活动状态的 Task 准入服务不能证明每个服务隔离范围都存在 backend。其 Agent 注册表和监听作用域也必须处理接收 Agent。按 Agent 查询信号会将这一关系与注入器生命周期绑定；其他注入器不能授权本地自动工作，也不能阻止直接的远端准入。本地授权要求调用上下文同时具备这两者。该上下文也选择投影注册表：接收器在另一个注册表中的注册项不能补足缺失的状态、客户端视图或证据。读取必需投影时会明确失败；自动准备缺少证据投影时，在预留额度前停止。

已完成请求的比较与自有自动活动的停止行为由[接收方证据决策](2026-10-03-recipient-evidence-activation.zh.md)定义。

组合准入根据本地字节数与固定包裹文字计算远端额度，Scope Access 在响应解码时强制执行该额度。到期和权限仍须独立检查，因为异步读取期间它们可能失效。持久化 schema 先确定投影类别和必需的请求锚点，再由历史校验检查授权、投影与精确消息之间的关系。

## 考虑过的替代方案

**将当前事实保留在较早的对话位置，并加强提醒。** 即使快照内容已更新，较后的轮次仍可能让它看起来属于历史。在此前工作之后追加已检查的快照可直接确立请求顺序，无需将事实复制进目标消息。

**把每个通知推入 Inbox。** 这可能强迫额外忙碌步骤，并在取消后遗留旧触发。待更新状态与单次自有空闲启动保留自然忙碌请求边界。

**空闲轮次复用已抓取的投影。** 预取可能在轮次开始前失去授权。admission 时独立读取保留在线权限要求。

**把上下文复制进每次自动提醒。** 排队后的提醒可能比触发它的证据存活更久。事实仅保留在经过 admission 校验的快照中，可避免在目标消息中重复或保留较早证据。

**让 `turn/end` observer 追加调度事件。** Session observer 运行时原 append 仍在发布。对已持久化结束事件的纯投影归约可提供同样状态，不需要重入写入或延后排序竞态。

**把所有拟议消息视为用户意图。** 其他插件可能给纯自动触发消息追加上下文。只有实际从 Inbox 领取的输入，才确立自动许可失败后仍有效的独立工作。

## 影响

自动工作需要显式开启，并受有限预算约束，同时具有明确暂停与恢复操作。当前权限仍依赖在线 owner。失败等待可通过显式恢复重建；不可用时绝不复用缓存事实。全部等待、读取、定时器和维护工作都具有 consumer 所有的取消与卸载结算。接入重入注册的 Agent 前先检查 consumer 生命周期；仅保护 Task 准入的 abort 回调仍会遗留替代 Agent 的恢复状态和监听器。历史上下文保持精确，当前可见上下文可以替换。

定向测试挂载真实 Loader 组合，用受控外部读取服务和无需密钥的 LLM adapter 驱动真实 AgentLoop。测试验证空闲与忙碌路径、精确替换、取消、混合输入、延后撤销、重放、完整字节上限、单次调度和生命周期收敛。跨进程传输与录制模型请求证据由独立集成 fixture 负责。此 consumer 不会唤醒任意外部终端会话，也不授予跨 owner 写入权限。 原生工作记录在来源 Agent 的下一次请求前等待此前操作的所有者回执。并发接收否则会改变其真实消息及轮次证明坐标；这些身份不做归一化。
