# Agent Note：原生 scope 变化投递与有界空闲轮次

Status: implemented

[English](2026-10-03-native-scope-change-delivery.md) | 中文

## 问题

具有独立上下文的原生 Agent 需要在协作者改变 Root Task 时获得当前授权的事实。要求 recall 调用会遗漏 Agent 不知道应当查询的事实。为每个网络通知启动轮次可能消耗无界工作、重新唤醒已取消输入，或把旧投影误当作当前权限。

## 决策

[Scope access](../../../../packages/collaboration/scope-access/README.zh.md) 在独立读取之外提供经过认证的有界 `waitForChange` 操作。不透明游标覆盖 owner、grant 和接收方代际、Task revision，以及 backend identity/configuration。游标匹配时等待变化直至配置的截止时间；未提供游标时在线校准。通知不含事实。游标不是授权租约、采用回执或启动模型请求的许可。

等待拥有独立的取消和最新等待所有权，不会覆盖读取。显式等待容量低于传输请求容量，等待截止时间低于 access 和 transport 截止时间。接收方等待时仍为普通读取和管理保留容量。撤销、过期、本地退出、owner 不可用和等待取消保持不同结果。backend identity 变化可以使游标失效，但不声称底层 Task 事实变化。

[原生 scope 上下文](../../../../packages/collaboration/scope-agent-context/README.zh.md) 通过经过认证的本地管理，将一个已经运行的普通 Session 绑定到独立读取订阅。已有本地分配需要明确的[组合接收同意](../feature/2026-10-07-retain-local-task-during-joint-receiving.zh.md)；职责是路由信息，不是 ACL。没有自动策略的绑定仅开启请求时读取。本地自动策略提供目标、全生命周期绝对启动次数上限、每轮步骤上限和最小间隔。远端来源文本不能授予此许可。

忙碌时的变化把绑定标记为待更新，不加入输入或强迫下一步。在自然 pre-step，consumer 独立在线读取，并在采用前检查当前 Agent、绑定、取消、终态和完整 UTF-8 文本上限。获得许可的空闲绑定合并通知，同一时刻仅拥有一次预取；之后短 Agent maintenance 活动预留一单位预算，并排入一条本地目标触发消息。获准的 pre-step 再次读取，不把预取当作离线授权租约。更新变化不会使原本授权有效的捕获投影失效而饿死投递，而是保留给后续请求处理。

Session 事件持久保存当前绑定、策略、累计预留次数和待启动 identity。投影也归约持久化的 `turn/end` 事件，以清除待启动记录，并在轮次未正常完成后暂停已启用策略。这避免从 post-commit 通知追加 Session 事件，因为该处禁止重入 append。已有显式暂停原因保持不变。取消、退出、重新绑定和重启不会退还预留次数，重放拒绝下降的计数。恢复的绑定在显式续许之前保持被动或暂停；恢复 Session 不会重放待执行的自动工作。

精确上下文以 user-role 消息记录，附带原始投影和权限元数据。首次采用通过 Loop 正常消息批次进入受保护的 system head 之后。后续消息只替换自有可见节点，保留历史事件。拒绝或不可用状态以撤回标记替换活跃上下文。这些操作不会擦除普通消息引用的事实，也不能证明模型遗忘了先前输入。

maintenance 中的取消会同步暂停本地自动许可，并且只删除自有触发消息。监听持续到返回的 maintenance promise 结算。Loop 取消会清除原有唤醒标记，同时按请求保留 Inbox 数据；在重入取消之前开始的 send 不能恢复该标记，之后明确发生的 send 仍可唤醒新工作。空闲网络预取时没有可取消的 Agent 活动，因此 `scopeAgentContext.pause` 是整个策略的停止操作。拒绝自动触发消息不会丢弃同批已领取的用户或插件工作。公开的 `agent/inbox/claimed` 事件在任何 pre-step listener 追加上下文之前提供输入 identity 和轮次。这些记录决定是否存在独立授权的工作，而不是可变的 waterfall payload 或派生上下文；每个 pre-step 消耗对应记录，轮次完成或卸载清除残留。

已完成请求的比较与自有自动活动的停止行为由[接收方证据决策](2026-10-03-recipient-evidence-activation.zh.md)定义。

## 考虑过的替代方案

**把每个通知推入 Inbox。** 这可能强迫额外忙碌步骤，并在取消后遗留旧触发。待更新状态与单次自有空闲启动保留自然忙碌请求边界。

**空闲轮次复用已抓取的投影。** 预取可能在轮次开始前失去授权。admission 时独立读取保留在线权限要求。

**让 `turn/end` observer 追加调度事件。** Session observer 运行时原 append 仍在发布。对已持久化结束事件的纯投影归约可提供同样状态，不需要重入写入或延后排序竞态。

**把所有拟议消息视为用户意图。** 其他插件可能给纯自动触发消息追加上下文。只有实际从 Inbox 领取的输入，才确立自动许可失败后仍有效的独立工作。

## 影响

自动工作需要显式开启，并受有限预算约束，同时具有明确暂停与恢复操作。当前权限仍依赖在线 owner。失败等待可通过显式恢复重建；不可用时绝不复用缓存事实。全部等待、读取、定时器和维护工作都具有 consumer 所有的取消与卸载结算。历史上下文保持精确，当前可见上下文可以替换。

定向测试挂载真实 Loader 组合，用受控外部读取服务和无需密钥的 LLM adapter 驱动真实 AgentLoop。测试验证空闲与忙碌路径、精确替换、取消、混合输入、延后撤销、重放、完整字节上限、单次调度和生命周期收敛。跨进程传输与录制模型请求证据由独立集成 fixture 负责。此 consumer 不会唤醒任意外部终端会话，也不授予跨 owner 写入权限。
