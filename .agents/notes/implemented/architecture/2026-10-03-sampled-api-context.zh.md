# Agent Note：接收者上下文中的 API 采样声明

Status: implemented

[English](2026-10-03-sampled-api-context.md) | 中文

## 问题

成功的工具观察不能确定文件当前的声明、它们与早期证据的关系，或对另一参与者的相关性。普通 publication 文本不能证明 Host 采样了获授权工件。存储失败后重新读取可能把新字节关联到早先的操作；仅清除采集权限也会让接收者上下文中的旧声明继续有效。

## 决策

[Claude 适配器](../../../../packages/collaboration/claude-scope/README.zh.md) 对支持的 OpenAPI 操作接受独立的精确文件读取授权。仅有工具目录授权不允许文件访问。配置的来源名称和操作在 Task 内标识逻辑 API；每项采集授权拥有自己的观察序号。不同路径不会自动标识同一 API，不同授权之间也不建立共同的因果顺序。

匹配已有 lease 的 Write/Edit 完成事件会采样获授权文件，包括报告失败的事件。读取器对同一次有界读取的字节计算摘要并解析，检查路径和句柄身份，提取受限的 OpenAPI 3.1 声明子集。不支持的输入、读取失败和替换会产生明确的证据状态，不保留部分事实。记录描述采样声明，不证明部署、完整校验或触发工具写出了这些字节。同用户恶意文件系统竞态不在可移植路径检查的威胁模型内。

串行适配器在 [Task 准入](2026-10-02-observed-task-context-admission.zh.md) 前保存提取的证据。待提交准入在重试或重启后复用同一份精确证据。Task 准入盖章观察节点和绑定归属，来源去重比较完整元数据，并要求同一授权中新序号递增。普通 Remote publication 不能提供可信观察元数据。可选且版本化的元数据保留既有无标注记录与继承块哈希。

仅 Host 可用的撤销操作证明此前已准入的链，不要求其 binding 仍然活跃。这允许外部清除 binding 后恢复撤销，而不接受迟到的普通观察。适配器先移除采集权限、耐久准备撤销，再完成撤销、清除 binding 并报告退出成功。失败保留足够状态供重试。Task 事件上限为每条活跃链预留一个撤销事件；恢复时会拒绝无法兑现预留容量的本地配置。

[事实 provider](../../../../packages/collaboration/development-task-context/README.zh.md) 在选择接收者字段前归约完整观察链。无效、不可用和已撤销的头记录不会恢复早期有效声明。每条链投影当前记录、最多一条前驱引用和已替代总数；更早来源明确标为因已替代而省略，避免历史耗尽当前事实预算。独立证据分歧保持未决；即使正常职责路由省略某些字段，冲突组仍保留全部竞争字段及其归属。路由不等于权限。预算包括完整组与包装文本，无法容纳时整组排除。继承 publication 始终是冻结的历史证据，不作为当前声明。

精确职责标签选择显式配置的字段。配置参与 provider revision。原生 Session 日志和外部准备输出记录保留精确投影文本；两种回放都不会从后来的文件重新计算事实。现有文本 provider 继续用于原始 publication。

## 考虑过的替代方案

**把任意 publication JSON 解释为采样事实。** 可解析 payload 或类似观察的 id 既不证明文件访问，也不证明来源权威。只有 Host 准入方法可以附加类型化元数据。

**选择最后到达的主张。** 独立授权之间没有共同采样顺序。按到达时间选择会隐藏不确定性；单项授权内的耐久序号只记录观察顺序，不宣称写入因果。

**仅在原 binding 仍有效时撤销。** 外部清除或重启可能发生在撤销之前。单独证明的撤销操作保留普通采集的严格 epoch 校验。

## 后果

获授权文件上的普通工作可以更新接收者声明，每次变化无需 publish 或 recall。支持子集和显式来源映射有明确限制：任意语义提取、无人值守文件监听、跨所有者授权、空闲唤醒及真实模型采用仍是[产品提案](../../proposed/architecture/2026-10-02-scope-context-backends.zh.md)中的独立要求。完整本地交付不证明外部模型使用了声明。

验证覆盖真实临时文件变化、伪造来源、乱序重试、耐久待提交准入、失效、中断撤销、容量预留、冲突预算、实际 command profile 以及原生请求回放。受控原生回放 fixture 证明请求和日志行为；适配器集成另行证明生产采样。
