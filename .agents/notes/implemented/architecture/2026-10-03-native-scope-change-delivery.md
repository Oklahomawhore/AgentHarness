# Agent Note: Native scope change delivery and bounded idle turns

Status: implemented

English | [中文](2026-10-03-native-scope-change-delivery.zh.md)

## Problem

A native Agent with independently owned context needs current authorized facts when its collaborator changes a Root Task. Requiring a recall call misses facts the Agent does not know to request. Starting a turn for every network notification can consume unbounded work, revive cancelled input, or mistake an old projection for current authority.

## Decision

[Scope access](../../../../packages/collaboration/scope-access/README.md) provides an authenticated bounded `waitForChange` operation in addition to independent retrieval. Its opaque cursor covers the owner, grant and receiver generations, Task revision, and backend identity/configuration. A matching cursor waits for a change until a configured deadline; an absent cursor calibrates online. Notifications contain no facts. A cursor is not an authorization lease, an adoption receipt, or permission to start a model request.

Waits have independent cancellation and latest-wait ownership, so they do not supersede retrieval. Owner capacity counts actual operations from the initial Task read through settlement. Cancellation or same-subscription replacement cannot release a still-running read; a retry at capacity returns unavailable. Task-change listeners register before the first read, so a commit during that read wakes the admitted wait without another registration read. Explicit wait capacity remains below transport request capacities, and the wait deadline remains below access and transport deadlines. A waiting receiver leaves capacity for ordinary reads and management. Revocation, expiry, local leave, unavailable owners, and cancelled waits remain distinct outcomes. Changing backend identity can invalidate a cursor without claiming that the underlying Task facts changed.

[Native scope context](../../../../packages/collaboration/scope-agent-context/README.md) binds one already live ordinary Session to a separate read subscription through authenticated local management. An existing local assignment requires explicit [combined receiving consent](../feature/2026-10-07-retain-local-task-during-joint-receiving.md); responsibility is routing information, not an ACL. Binding with no automatic policy only enables request-time reads. A local automatic policy supplies a goal, an absolute lifetime activation limit, a per-turn step limit, and a minimum interval. Remote source text cannot grant this permission.

Busy changes mark the binding dirty without adding input or forcing another step. At a natural pre-step, the consumer performs an independent online retrieval and checks the current Agent, binding, cancellation, terminal state, and complete UTF-8 text limit before adoption. An idle authorized binding coalesces notifications and owns at most one prefetch; a short Agent maintenance activity then reserves a budget unit and queues one locally sourced goal pulse. The admitted pre-step reads again rather than using the prefetch as an offline authorization lease. A newer change does not invalidate an otherwise authorized captured projection and starve delivery; it remains pending for a later request. Replacing or retiring a binding synchronously aborts its captured watch signal; checking that signal after each await also prevents an old wait from clearing a replacement watch. Local invalidation carries the caller’s already selected local binding and rechecks its identity before deferred withdrawal.

Idle withdrawal claims Agent maintenance before setting the receiver's maintenance flag. If another activity owns the Agent, withdrawal waits for the next normal admission without interrupting subscription cleanup. It neither cancels that activity nor retains a false maintenance claim. Automatic activation also claims maintenance before setting its flag; a busy claim preserves permission and budget, and the existing dirty scheduler continues without another resume command.

Session events persist the current binding, policy, cumulative reservations, and pending activation identity. The evidence projection independently validates request reservations and suppression baselines for cold readers; live-Agent history validation cannot replace it. An identical pending-state record preserves its reservation; changing its activation, binding, goal or enabled state invalidates that reservation. The projection also folds durable `turn/end` events to clear pending activation and pause an enabled policy after a non-completed turn. This avoids writing another Session event from its post-commit notification, where reentrant append is forbidden. Explicit pause reasons remain intact. Reservations are not refunded after cancellation, leave, rebinding, or restart, and replay rejects a decreasing reservation count. Restored bindings remain passive or paused until explicit renewal; restoring a Session does not replay its pending automatic work.

Task and scope consumers log exact context as user-role messages with source and authority metadata. First admission uses the Loop's normal message batch after the protected system head. Changed context clears only owned visible nodes using empty plugin messages, then appends the exact current snapshot after prior work. Session derivation omits empty user nodes, so the request contains one current context per selected source while the log retains every source event and replacement link. Denial or unavailability uses the same ordering for its withdrawal. Live and detached Sessions use the same replacement operation, so cold departure does not construct an Agent. The automatic reminder carries only the authorized goal. These operations do not erase facts quoted by ordinary messages or prove that a model forgot earlier input.

The passive Task consumer restores unsubmitted inputs when context preparation fails and propagates the error. The Loop has already claimed those inputs before admission; a new explicit user continuation owns the retry. The Task service commits assignments and their retained binding events synchronously; the consumer trusts that projection. Cordis removes the consumer’s event listeners before aborting its admission lifetime, and request admission checks cancellation before acknowledgement. Native status, passive receiving and local collection share the Task service’s last retained task-bound selection in durable order, independent of clocks or binding names. Exact local reads verify the requested binding rather than the first participant match. Retained event selection also requires the current binding to belong to the requested participant; reusing a cleared binding ID for another participant cannot expose their Task. Selecting another binding ends old local collection without renewing consent. The Task injector checks its own cancellation before returning a delegated rejection, so simultaneous Scope and Task unload retains ordinary claims while their original Agent request remains live. Native cancellation with discarded inbox input prevents restoration.

Cancellation in maintenance synchronously pauses local automatic permission and removes only owned pulses. A consumer stopping its own automatic turn publishes the existing idle-settlement promise before requeueing inputs or emitting cancellation. Reentrant replacement permission waits for that settlement, so the retiring turn cannot pause the replacement permission. The listener remains installed through settlement of the returned maintenance promise. Loop cancellation clears a pre-existing wake latch while retaining requested inbox data; a send that began before a reentrant cancellation cannot restore that latch, while a later explicit send may wake new work. During idle network prefetch there is no active Agent activity to cancel, so `scopeAgentContext.pause` is the policy-wide stop operation. A rejected automatic pulse does not discard user or plugin work claimed in the same batch. The public `agent/inbox/claimed` event supplies the input identity and turn before any pre-step listener can append context. Those records, not mutable waterfall payloads or derived context, determine whether independent work remains authorized; each pre-step consumes its records, and turn completion or disposal clears leftovers. Replacement permission only awaits quiescence, so a completed settlement needs no separate cleanup state.

Automatic turn ownership starts with the matching Inbox claim, before another pre-step listener can suspend the turn. Receiver attachment requires the exact live Agent in the injected registry. Dispatch settlement also checks the request marker’s exact Session object, because isolated registries may reuse IDs and a nested foreign request may inherit the original registry’s asynchronous initiator. Unloading Scope cancels that activity even if its admission listener has not begun. A captured listener that has not begun delegates after unload. An ordinary request already preparing inside Scope is rejected on unload with its unsubmitted claims retained; an already admitted model request can finish without further Scope evidence. Reentrant registration of another live Agent under a removed registry entry retires the previous receiver before the earlier disposal notification can finish.

Automatic activation checks permission when a scheduled callback starts: an old timer may fire between queued ordinary turns before an idle notification. Activation and binding cancellation invalidate asynchronous preparation; only one activation reserves the lifetime budget. Native maintenance claims and invokes its job synchronously, while the reservation retains the latest state, including route changes. Resume compares its non-null expected binding before any scheduling write. A departed Session rejects that stale identity without changing its log.

Terminal watcher results synchronously pause permission and abort pending activation preparation before reservation. Ordinary admission does not share that activation signal: it preserves independent user work and applies the observed terminal outcome to a late read.

An active Task admission service does not establish a backend in every service-isolation realm. Its Agent registry and listener scope must also handle the receiving Agent. One Agent-specific signal query ties this relation to the injector lifetime; foreign injectors cannot authorize local automatic work or suppress direct remote admission. Local authorization requires both in the calling context. That context also selects its projection registry: the receiver’s registrations in another registry do not supply missing state, client views, or evidence. Required projection reads fail explicitly; automatic preparation stops before reservation when its evidence projection is absent.

Completed-request comparison and stopping owned automatic activities are defined by the [recipient evidence decision](2026-10-03-recipient-evidence-activation.md).

Composite admission derives the remote allowance from local bytes and fixed framing; Scope Access enforces that allowance when decoding the response. Expiry and authority remain independent checks because asynchronous reads can make them stale. Durable schemas establish the projection kind and required request anchors before history validation checks relationships between authorization, projections, and exact messages.

## Alternatives considered

**Keep current facts at an earlier conversation position and strengthen the reminder.** Later turns can make an earlier snapshot appear historical even when its contents have changed. Appending the checked snapshot after earlier work establishes the request order directly without copying facts into the goal message.

**Push every notification into the Inbox.** This can force extra busy steps and leave stale triggers after cancellation. Dirty state and a single owned idle activation preserve natural busy request boundaries.

**Reuse a fetched projection for an idle turn.** A prefetch can become unauthorized before the turn begins. Independent admission-time retrieval preserves the online authority requirement.

**Copy context into each automatic reminder.** A queued reminder can outlive the evidence that prompted it. Keeping facts in the admission-checked snapshot avoids duplicating or retaining that earlier evidence in the goal message.

**Let `turn/end` observers append scheduling events.** Session observers run while the original append is being published. A pure projection fold of the already durable ending provides the same state without reentrant writes or deferred ordering races.

**Treat every proposed message as user intent.** Another plugin can append context to a pure automatic pulse. Only input actually claimed from the Inbox establishes separate work that survives automatic permission failure.

## Consequences

Automatic work is opt-in and finitely budgeted, with explicit pause and resume. Current authority remains dependent on an online owner. Failed waits can be restarted by explicit resume; unavailability never reuses cached facts. All waits, reads, timers and maintenance work have consumer-owned cancellation and disposal settlement. Attachment checks the consumer lifetime before adopting a reentrant Agent registration; guarding only the Task admission abort callback leaves a replacement's restored state and listeners behind. Historical context remains exact while current visible context can be replaced.

The focused suite mounts a real Loader composition and drives the real AgentLoop with a controlled external read service and a keyless LLM adapter. It validates idle and busy paths, exact replacement, cancellation, mixed input, late revocation, replay, complete byte limits, single-flight scheduling and lifecycle drainage. Cross-process transport and recorded model request evidence belong to their separate integration fixtures. This consumer neither wakes arbitrary external terminal sessions nor grants cross-owner write permission. The native-work recording waits for each preceding operation’s owner receipt before the source Agent’s next request. Concurrent receiving otherwise changes its authentic message and turn-proof coordinates; these identities remain unnormalized.
