# Agent Note: 按收件人证据控制自动激活

Status: implemented

[English](2026-10-03-recipient-evidence-activation.md) | 中文

## 问题

重复采样可能改变来源标识、版本和审计历史，却没有改变与收件人有关的事实。每次精确投影变化都启动自动工作，会把有限的协作额度消耗在这些变化上。但减少比较内容也有风险：更正、冲突、撤回或当前证据缺失可能从调度判断中消失，尽管模型仍需要处理它们。

## 决策

[收件人上下文后端](2026-10-02-recipient-task-context-backend.zh.md)在精确正文和完整来源覆盖信息之外返回激活描述。`exact` 保留精确投影比较；`recipient-evidence` 为能够确定性定义收件人比较规则的后端提供带版本的摘要标识和当前覆盖状态。该描述用于判断是否需要另一轮自动工作；它不授予读取权限，也不替代模型输入或审计记录。

确定性 OpenAPI 事实提供者比较按显式规则路由的当前声明。摘要标识保留 Task 指令、后端配置、各独立来源及授权身份、缺失字段、无效或不可用证据、冲突和终结通知。冲突包含全部受支持的事实字段。样本标识、序号、文件哈希、时间戳和已被替代的历史仍保留在 Task 审计日志中，但不会单独触发工作。交付正文及已选择或已省略的来源引用仍保持精确。冻结的继承证据仍属于历史。两次读取之间发生又恢复的变化仍可审计，但系统不声称模型处理了每个中间状态。

若字节上限使整个当前证据组或终结通知被省略，覆盖状态就是 `blocked-current`。原生消费者暂停自动工作、撤下当前上下文，且不从该投影建立已完成基线，也不回退到较早的有效样本。仅省略已被替代或冻结的历史记录不会阻断当前证据。在用相等判断抑制工作之前，完整模型正文及消费者附加说明必须符合预算。

精确比较不表示证据完整。如果任何 backend 将属于当前 Task 及其版本的 publication 标为 `budget` 省略，原生消费者同样阻断自动工作。空闲启动及每次自动请求准入共用此项检查，所以触发消息已预留或工具步骤完成后出现的超限更新也无法通过。空闲检查不新增预留；已预留的次数仍计入消耗。被阻断的自动继续步骤若无新的人类输入，就拒绝请求。混合输入保留普通人类工作和明确的上下文撤回。使用文本 backend 的普通用户请求仍接收有界上下文及省略信息。非预算省略本身不会触发这项额外检查。

[Scope access](../../../../packages/collaboration/scope-access/README.zh.md)将该描述纳入版本 2 的投影哈希。严格解析保留未版本化精确记录的原始哈希，并拒绝不完整的版本化记录。未版本化记录采用精确比较。每次调度评估仍在线读取并检查当前读取权限；摘要相同不构成离线许可。已提交的 Session 代际保持不变。

[原生消费者](2026-10-03-native-scope-change-delivery.zh.md)仅根据已获准的自动额度预留、实际冻结的 AgentLoop 请求、该请求对应的未中断 assistant 消息和整轮完成事件推进基线。首次请求必须携带匹配的本地 pulse。该请求确定后续步骤所属的自动轮次，即使压缩移除了历史 pulse 也不改变归属。每个新步骤清除上一派发候选；最后一个实际请求提供基线上下文。最终请求没有 scope 快照时不能借用较早步骤。完成记录证明目标尝试已执行，不证明目标已经实现。

评估事件保留精确候选投影及已完成基线引用；请求事件引用实际派发的精确已记录上下文。普通用户轮次和预取不建立自动基线。抑制要求本地绑定、显式目标、授权及后端比较均相同。重新加入或更换目标不能复用已完成基线。续期相同目标可以复用已完成的等价证据；仅修改额度或节奏不会使事实变新。被抑制的空闲评估不消耗预留额度，但准入前已预留的 pulse 仍计入消耗。恢复的自动绑定保持暂停，直到显式续期。

暂停、离开、替换绑定和卸载消费者会取消其拥有的自动活动，防止它继续作为普通工作运行。取消所需的活动归属从实际 Inbox 领取输入时开始，早于其他 pre-step 监听器可能发生的等待。尚未派发的用户或插件输入仅返还 Inbox 一次。已经派发的混合请求会被中断，且不重放其中的用户输入；没有受管自动活动的普通轮次不会因离开 scope 而被取消。重新绑定和续期等待旧活动结束后才提交新许可，并复查存活 Agent 和命令身份。卸载等待取消的活动结束。

类型化的 `agent/cancel-requested` 事件报告每次取消调用，包括活动信号已经中止后的调用。它保留首次中止原因，同时让后续 Stop 使等待中的绑定或恢复操作失效。消费者仅排除自己同步取消所使用的同一 cause 对象；重入的用户 Stop 仍具有优先权。监听器只改变命令顺序，不追加 Session 事件。这个事件是必要的，因为已经中止的信号无法报告第二次取消请求。

## 考虑过的替代方案

**仅比较精确投影标识。** 文本及其他精确提供者继续采用此策略。它无法区分新采样记录与新的收件人证据，因此会为仅涉及审计的变化消耗自动工作。

**从渲染正文中去除元数据，再计算剩余内容的哈希。** 呈现方式不能定义证据身份。去除看似元数据的内容可能抹去来源变化或冲突归属，而文本格式变化又可能产生虚假差异。事实提供者在归约来源时同时定义比较规则。

**将预取、准入或一个成功步骤视为已完成工作。** 这些情况都不能证明最终实际请求包含相关证据且整个自动轮次完成。失败、取消、截断或后续不含上下文的请求不能利用较早候选推进基线。

**将任意成功的用户请求作为自动基线。** 用户可以在接收 scope 上下文时询问无关问题。该请求不能证明系统尝试了另行获准的自动目标。

## 影响

事实提供方的收件人比较覆盖显式 OpenAPI 字段路由及其确定性证据状态。它不是通用语义相似度或 embedding 通信，也不验证已部署 API 的行为。文本和[报告文件](../feature/2026-10-07-reported-file-context.zh.md)后端使用精确比较。这两个提供方不判断语义相关性，因此任何因容量而省略的当前 publication 都会阻断自动工作，即使人认为这条 publication 无关。来源准入、精确投影和审计存储仍随观察记录增长；本决策减少重复自动模型轮次，不丢弃其来源信息。

后端用例验证比较稳定性和有效变化触发。使用真实 Loader 和 AgentLoop 的测试通过受控 scope 服务及无需密钥的 LLM 适配器，验证冻结请求归属、多步完成、重放、取消、混合输入、续期和卸载。无需密钥的 SDK `scope-owner-idle` 场景在自动轮次完成后，通过真实 peer 文件采集提交完整的超限报告，再验证覆盖不足导致暂停且没有新增预留或派发。这些测试证明调度及日志语义，不证明模型推理质量、现实协作成功或跨物理设备部署。
