# Agent Note: 在一次明确授权下共享原 Claude 会话的工作

Status: implemented

[English](2026-10-14-original-claude-work-contributions.md) | 中文

## 问题

一个人原有的 Claude 会话会在同一职责内产生文件操作、命令报告和答复。仅共享文件会遗漏相关工作，另建报告会话则改变了用户的工作方式。Claude 钩子不提供[原生工作贡献](2026-10-14-combined-native-work-sources.zh.md)所要求的原生进程与完整轮次证据。

## 决策

[Claude 适配器](../../../../packages/collaboration/claude-scope/README.zh.md)使用独立的版本 7 `claude-work` 来源。用户分别选择文件工具、精确命令和完整 Stop 答复报告，再由所有者一次批准完整选择。后续每条获准观察共用同一采集、累计额度和既有贡献控制器。原有权限不会获得额外类别，各协议版本也不会相互替代。

命令观察保留钩子的原始字段，不推断退出码。同一采集、目录和命令的新报告替代此前报告，即使新结果为中断或未知。Stop 报告保留原始答复及其摘要值；它既不证明完成，也不替代独立答复。完整答复可能引用用户的私有输入，因此表单在用户同意前说明这一后果。

Stop 采集要求当前提示词身份来自已授权的 UserPromptSubmit。本地提示词失效先于远端恢复；待发送的贡献不能让此前提示词继续有效。新提示词、匹配的 StopFailure、采集终止和 SessionEnd 都会使该权限失效。重启丢弃未完成的提示词权限，同时保留已准备的报告供精确重试。持久化的工具与 Stop 记录共用既有保留上限。

[上下文后端](../../../../packages/collaboration/development-task-context/README.zh.md)将这些报告视为可归属的来源证据。采集不分配工作、不授予工具权限，也不唤醒空闲的外部会话。[既有的人类职责](../process/2026-10-05-collaboration-follows-human-responsibility.zh.md)仍是独立 agent（智能体）存在的原因。

## 考虑过的替代方案

**复用原生结果类型。** Claude 的 Stop 事件不能证明轮次完成，其命令钩子也不能证明原生进程退出码。复用这些类型会赋予报告超出来源证据的含义。

**读取完整 transcript（文本记录）或另建报告会话。** 两者都会引入所选原会话获准事件之外的信息或工作流程。明确的类别选择保留单一采集生命周期，无需复制私有会话历史。

## 后果

一次审阅后的授权支持自动共享工作，无需逐条发布。整字段省略、到期和撤回仍然可见；报告成功不等于经验证的当前事实。既有读取权限与执行权限保持独立。

验证需要覆盖来源生命周期回归、严格的协议与持久化解析、原始字段保留，以及两个 SDK 中可重建的接收方请求。SDK 中的合成来源能够验证传递，但不能证明外部 CLI（命令行界面）采集、模型理解或人工沟通减少；这些需要独立的端到端证据。

适配器先核验所有工作记录所属的 Session 代际，再逐一恢复 capture。每个 capture 的恢复在重试证据前检查原始本地身份、工具授权、样本身份与序号，以及 owner 回执。这些检查拒绝单独可解析、但属于另一权限或完成事件的耐久关联，不扩大较早的采集同意。服务回归通过重启检验被篡改的持久记录，覆盖订阅分配前后的联合撤回，以及同时存在的旧版会话与 Claude-work 会话之间的隔离。
