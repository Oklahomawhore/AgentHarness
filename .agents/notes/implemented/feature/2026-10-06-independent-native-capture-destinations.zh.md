# Agent Note: 本地与对等采集目标分别授权

Status: implemented

[English](2026-10-06-independent-native-capture-destinations.md) | 中文

## Problem

一个人的现有 Agent 可以负责本地 Task，同时向另一个人的 Task 贡献获准的文件工作。要求 Agent 先退出本地职责会阻碍这种协作。两个目标共用一份运行时选择，还可能把完成记录归到错误许可，或停止无关的采集。

## Decision

[原生贡献消费者](../../../../packages/collaboration/scope-agent-contribution/README.zh.md)允许一个普通 Session 同时持有一份本地采集和一份独立对等采集。每个目标分别持有同意、采集身份、操作取消、未完成观察、完成记录保留、重试任务和停止操作。`stopLocal` 选择本地授权，`stop` 选择对等授权。另一个目标的采集身份属于陈旧选择，不能作为切换目标的指令。

实际文件系统操作分别接受两份存活许可的检查。每份获准报告保留原工具派发、提供方、路径选择、结果和 Session 耐久检查点。本地报告不会被转发给对等方。每份采集的样本上限独立计算；服务的观察保留上限统计两个目标。一个许可失败或撤回，不会取消另一个许可。

本地授权绑定精确的 Task 分配世代。对等采集遵循独立批准的 Session、目录、工具、目标和限额。改变本地分配会终止本地采集，但不改变对等同意。单独释放 Agent 会终止两份采集。重启会完成两份保留的终止操作，不会向替代 Agent 授予采集许可。两个独立持久化域保留原有表示。

这项决策替代[所有者本地贡献决策](2026-10-04-owner-local-scope-contributions.zh.md)中的采集互斥要求。读取和自动执行仍分别授权：向对等方贡献不会替换本地 Task，也不授予接收外部 scope 的权限。原生接收服务仍限制本地 Task 与对等订阅同时存在。

## Alternatives considered

**把本地文件许可当作所有 scope 的许可。** 增加目标会改变文件内容的接收方。每个目标都需要明确同意和独立授权检查。

**复用本地报告发送给对等方。** 不同目录、工具、字节限额和有效期，可能允许同一操作的不同内容。复用完成报告会丢失这些区别。

**保留一个 Session 级停止操作，推断其目标。** 两份采集可以同时合法存在。根据先查到的记录推断，会使停止和重试影响无关授权。

**本地 Task 改变时终止对等采集。** 对等同意记录 Session 和文件选择，不记录本地分配世代。推断这层关系会悄悄重新解释现有持久化同意。

## Consequences

已有工作的 Agent 可以向另一个所有者贡献，同时保留本地分配和采集。独立运行状态增加了生命周期管理工作；现有共享管理队列仍负责串行提交持久状态。独立目标测试与已交付配置的 Session 回放验证授权、路由、撤回和本地工作的保留。它们不证明本地与对等联合接收、模型语义质量，或人为拆分任务的收益。
