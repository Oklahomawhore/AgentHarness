# Agent Note: 依据获准报告重建文件文本

Status: implemented

[English](2026-10-07-reported-file-context.md) | 中文

## 问题

一个小文件也可能积累足够多的 Edit 报告，耗尽接收者的上下文预算。即使最新报告所描述的文件文本能放下，整链准入也会排除全部报告。分享私有工具执行结果或读取原文件会披露既有报告许可之外的内容。

## 决策

[Task 上下文包](../../../../packages/collaboration/development-task-context/README.zh.md#behavior) 提供具有独立后端身份的 `/reported`。它依据满足条件的完整实时 Write/Edit 报告推导文本，不访问文件系统，也不调用模型。Web 默认选择该提供方；`/text` 保留原始 publication，`/semantic` 保持其独立输入与校验规则。所有提供方都使用既有交付与耐久投影机制。

重建扩展[完整 Write 检查点](2026-10-04-tool-report-checkpoints.zh.md)，但不声称掌握当前文件系统状态。完整实时 Write 只确立报告中的基底。采集序号连续、受支持的字面编辑以及不变的授权共同约束派生记录。未知序号位置、历史初始化、不受支持的字符或操作结果，以及 publication 附带的额外语义，都会保留不可拆分的原始链。其他文件的已知观察可确立中间采集位置。当前快照与冻结快照不能互相提供基底。

派生文本携带明确的报告状态说明和紧凑依赖信息。精确选中来源仍保存在投影与 Session 记录中，包括恢复到早先值的操作。撤回和接收者排除先于重建。完整输出与中间文本都受接收者字节上限约束；失败不能恢复过时基底。提供方采用精确激活比较，不创建执行许可。

## 考虑过的替代方案

**增加上下文预算。** 持续编辑仍会累积报告，这只能推迟失败。新表示让部分有界文件在既有预算内保持可用，但不限制已存历史。

**导出原生工具产生的完整文件。** 结果可能包含仅输入报告许可未授权的既有私有内容。使用这种更广泛的来源前，需要单独的文件状态许可。

**将重建结果视为当前文件事实。** 其他写入者和未报告操作仍不可见。派生记录只说明所选报告能够推导出的内容。

**将所有文本后端替换为重建内容。** 消费者可能需要原始 publication，语义引文也使用独立的审计来源格式。独立提供方保留这些选择，不改变既有日志投影。

## 影响

满足条件的文件可在较长编辑序列后继续提供有效上下文，无须辅助模型调用。缺少获准完整 Write 的文件、不受支持的报告和过大的派生文件仍可能耗尽预算。精确覆盖信息、publication 和请求历史持续增长。本决策不确立语义等价、费用收益、模型理解或物理设备连通性。

验证覆盖完整包裹预算、序号缺口、Unicode 与字面替换、原始报告回退、撤回、接收者排除及快照隔离。真实原生工具验收将独立读取的文件内容与接收方请求比较。已记录 Session 与 Python SDK 场景保留完整出处，并从耐久事件重建交付。受控模型回复验证的是传输与表示，不是任务质量。
