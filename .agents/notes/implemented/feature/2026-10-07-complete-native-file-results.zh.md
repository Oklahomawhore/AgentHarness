# Agent Note: 显式分享原生文件操作的完整结果

Status: implemented

[English](2026-10-07-complete-native-file-results.md) | 中文

## 问题

已有项目通常通过 Edit 修改，而不是重新执行完整 Write。只分享输入参数无法还原文件中未修改的内容，不可拆分的长 Edit 历史也可能超出接收方上下文额度。为补齐信息而读取文件会泄露原输入分享许可之外的文本，还可能采到后续写入者的状态。

## 决策

[原生贡献](../../../../packages/collaboration/scope-agent-contribution/README.zh.md) 为本地分享和独立所有者批准的远端分享提供单独的 `completed-native-file` 选项，沿用明确选定的目录、工具、到期时间及完整采样额度。来源版本 3 授权结果版本 3；普通及既有记录输入许可不会获得这项权限。历史初始化与完整内容许可互斥，Claude Hook 采集拒绝这项原生专用许可。

[文件工具](../../../../packages/fs/tool-fs/README.zh.md) 携带原先准入的 mutation 身份发出同一 provider 产生的完整 LF 规范化结果。采集只在原完整内容许可下保留它，将其关联到最终普通或 PTC 结果，并在来源 Session 刷盘后准入。最终结果失败不能发布完整文本。完整载荷额度省略整个完成文件正文而不截断它，原始参数保持既有的整字段预算规则。来源持久化与 worker 顺序在重试期间保留原完成顺序；停止及许可变更阻止待处理内容准入。

[reported 后端](../../../../packages/collaboration/development-task-context/README.zh.md) 将该授权文件的最新完整结果作为独立完整依据呈现。更早报告标记为已替代，但原发布及已送达 Session 历史不会删除。后续失败和省略仍位于同一不可拆分片段，不能悄悄回退为只显示旧文件。撤回会移除已准入正文；text 与 semantic 后端保留原有报告选择规则。

## 考虑的替代方案

**每次 Edit 后读取文件。** 二次读取需要独立的文件系统策略，可能看到其他写入者的内容，也不能恢复精确的操作结果。生产方已经持有该结果。

**应用未知基底的 Edit 片段。** 片段无法证明未修改的文本；摘要仍缺少协作所有者需要的文件内容。

**为已有采集开启完整内容。** 输入许可不涵盖已有文件中未修改的部分。用户必须一次选择更大的范围；之后普通工作无需逐次执行分享动作。

## 后果

接收方可在已有文件首次获准 Edit 后收到完整操作结果。文本包含未修改部分，可能比输入报告占用更多来源和网络容量。它不证明当前磁盘状态、后续或外部工作、部署行为或模型理解。完整来源、传输、模型及保留量额度仍然有限；双设备可用性与付费模型的生产力收益需要独立验收证据。
