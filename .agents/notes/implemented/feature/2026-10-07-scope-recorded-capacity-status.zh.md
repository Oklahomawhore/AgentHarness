# Agent Note: 协作入口持续展示记录中的容量遗漏

Status: implemented

[English](2026-10-07-scope-recorded-capacity-status.md) | 中文

## 问题

被动接收的 Session 可以使用有界的部分共享上下文继续工作。工作模式描述调度，不描述来源覆盖。计数藏在接收面板内时，用户需要主动检查后台同步才能发现输入缺失，尤其是在仍选中原有本地 Task 时。

## 决策

[当前 Session 入口](../../../../packages/client/ui-emergence-center/src/client/NativeScopeAction.tsx) 根据当前精确绑定已记录的共享上下文显示容量提示。它要求接收状态已就绪、符合接收条件、本地订阅有效，且绑定与订阅身份匹配。管理操作待完成、状态不可用、离开、撤回或记录不匹配时，提示消失。其他排除原因不转为容量警告。

收起的入口保留原可访问名称，并通过描述提供记录中的排除计数。窄屏保留简短的可见提示。打开提示会选择远端接收面板，由提供方、职责和既有计数标明受影响的协作。说明将摘要方式的问题指向该提供方，不提供无法改变远端的接收方本机设置。选择面板不更改权限，也不请求上下文。

既有[已记录上下文状态](../../../../packages/collaboration/scope-agent-context/src/recorded-context.ts)及步骤或生命周期失效通知提供这些数据，不新增 Session 事件、轮询、后端选择或自动执行。

## 考虑过的替代方案

**仅在详情中保留计数。** 收起入口只报告调度或本地采集状态时，用户无法知道何时需要检查详情。

**阻止普通工作或自动启用摘要。** 容量遗漏不能证明相关性。阻止普通工作会改变被动接收语义；自动摘要则会在提供方未明确选择时消耗模型调用，并影响其其他 Task。

## 影响

用户无需维护消息流即可发现记录中的容量缺失。提示不判断哪些被省略来源重要，不补回省略内容，也不证明请求已发送、模型已理解或远端当前仍授权。计数为零不代表完整。既有读取错误与自动工作状态保持独立。

Client 验证覆盖本地化可访问计数、本地职责保留、身份替换、Session 变化与非当前状态。[Web 接收场景](../../../../apps/web/tests/native-owner-contribution.e2e.ts) 将提示与实际准入投影比较，并检查桌面与窄屏展示。受控请求证明展示和准入，不证明模型收益或物理跨设备可靠性。
