# Agent Note: 一次原生加入保留独立的读取与贡献许可

Status: implemented

[English](2026-10-04-native-joint-join.md) | 中文

## 问题

独立 Task 参与者需要传递贡献入口和另一份读取邀请，才能接通一个既有 Agent。在线申请已经认证来源 peer，用户仍需要重复转录身份。在响应不确定后重新签发邀请或执行绑定会创建新的身份，也可能覆盖后来的本地选择。将贡献终结视为全部参与结束，还会丢失另行授权的读取。

## 决策

显式联合入口选择一个原生 Session 采集。来源同时确认读取完整 Root Task 和有限的本地文件工具结果采集。同一申请可通过初始关闭的本地自动工作选项记录有限目标和额度；本地根目录与执行策略仍由来源持有，不进入所有者申请或批准消息。所有者批准读取和等于或小于来源同意范围的贡献授权。既有贡献入口保持仅贡献的含义。[Scope 访问](../../../../packages/collaboration/scope-access/README.zh.md)先保留两项授权计划，再独立恢复各项提交，并分别报告每项权限。

[原生来源](../../../../packages/collaboration/scope-agent-contribution/README.zh.md)保留原采用身份和读取状态序号。响应必须先通过贡献邀请、回执与读取授权检查，才能产生可执行的读取工作。贡献激活或经过验证的贡献终态回执移除待处理申请后，读取才开始执行。贡献终态响应在同一来源行中原子地将未完成读取移交给一条有界后续记录，不撤销读取，也不授予新的采集权限。

[原生接收者](../../../../packages/collaboration/scope-agent-context/README.zh.md)持久保存原订阅与绑定计划、采用 Session 事件和终态取消。采用要求原接收状态及同一个在线 Agent 实例。已有本地 Task 的参与者按[组合接收决策](2026-10-07-retain-local-task-during-joint-receiving.zh.md)明确确认其精确分配。普通消息不会使同意失效，后来的手工读取决定会使其失效。重试已结束操作不能重新打开它。邀请相同不足以证明绑定归属。

自动响应使用参与者自己的本地目标和既有工具权限；所有者填写的职责文本和采集根目录不授予工具执行权。仅远端的自动计划使用 join-read version 2，被动计划使用 version 1；保留本地分配的计划使用 version 3。采用一同记录绑定和策略，调度等待 Session 检查点成功。绝对累计额度保留已消耗的预留次数；精确重试不能增加额度或撤销后来的暂停。首次 Context 计划之前，来源同意属于接受它的接收服务；计划建立后，它也属于原 Context consumer 和在线 Agent。卸载或更换该实例会取消待采用操作。这些运行时检查不在重载间转移权限。

停止分享取消待采用读取，保留 Session 已经采用的读取和自动许可。完整退出结束原贡献及其持有的本地读取绑定，不影响后来手工建立的绑定。这些意图先持久保存，再执行异步清理。读取工作在来源修改队列之外运行，因此慢读取或清理不会阻止另一 Session 记录停止。重启取消旧待处理工作，不向新 Agent 实例授予权限，也不启动冷 Agent。自动工作需要独立的本地决定。

## 考虑过的替代方案

**浏览器顺序调用。** 连续的申请、绑定与恢复调用无法在关页后可靠完成，也无法在丢失响应后确定成功许可的归属。Host 持有原参与操作的恢复工作。

**贡献与读取共用生命周期。** 清除采集会丢失待处理读取，即使其独立授权仍有效。有界后续记录只保留完成原操作所需的工作，不引入第二套权限权威或无界加入历史。

**重新签发身份或刷新同意。** 新邀请、订阅或读取状态序号可能绕过后来的取消或手工选择。恢复使用原身份和原观察状态。

**可复用群组码。** 多个申请者需要独立的申请身份和容量语义。已实现的入口只选择一个 Session 采集。

## 影响

一次入口传递和一次所有者明确批准接通读取与贡献，同时保留两者的独立状态。这降低初始接入成本，但不证明模型质量、跨物理机可达性或人工协调量下降。职责文本用于上下文路由，不限制获授权 Root Task 的内容。

未结算的后续记录阻止新采集覆盖原工作。已采用读取不再需要来源后续记录后，后续退出由独立读取面板负责。本地退出离开原订阅，不宣称所有者已经撤销读取授权。Session 日志仍是已采用上下文的权威，并支持两种 SDK 投影。
