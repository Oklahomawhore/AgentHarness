# Agent Note：自动协作活动记录

Status: implemented

[English](2026-10-06-recorded-collaboration-activity.md) | 中文

## 问题

许可与已消耗预留次数不能说明自动响应是否实际请求了模型、是否完成，或是否因证据未变而跳过。证据未变的评估不会修改调度状态，只观察该状态的客户端无法呈现已记录的决定。

## 决策

[原生上下文消费组件](../../../../packages/collaboration/scope-agent-context/README.zh.md)从现有证据折叠中投影不含正文的元数据。Status 在同一个 Session 水位读取调度和活动，再将活动限定于当前符合资格的绑定和已明确授权的本地目标。该机制不增加 Session 事件、执行权限或调度决定。

[会话协作面板](../../../../packages/client/ui-emergence-center/README.zh.md)订阅两类投影，并通过 status 核对状态。它区分预留与实际请求，在展示后续评估时保留最近一次成功完成。证据不完整可能在先前请求后阻止继续执行，因此面板报告后续请求已暂停，不声称响应尚未开始。断线、许可缺失、目标结束或不再符合资格时隐藏卡片。恢复的记录只描述历史，不代表许可已恢复。

## 考虑过的替代方案

**从预留用量推断进展。** 被取消的预留可能从未调用模型，证据未变的评估也可能不消耗预留次数。

**向面板发布完整证据。** 卡片需要已记录的序号、身份和决定，不需要共享上下文正文或本地目标文本。完整证据仍可通过现有轨迹查看。

## 影响

用户可以查看自动响应，无需维护 room 对话。面板不证明当前远端授权、网络活动、模型理解或产物正确性。记录会话回放及真实 Host/浏览器场景负责观察和刷新验证，已提交的 Session 日志保持不变。
