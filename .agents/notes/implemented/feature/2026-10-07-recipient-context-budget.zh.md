# Agent Note：共享上下文使用接收者剩余容量

Status: implemented

[English](2026-10-07-recipient-context-budget.md) | 中文

## Problem

每个人保留独立 Agent，其上下文容量可能不同。共享端按自身上限生成的投影，在加上接收者原 Task 和递送说明后可能超出接收容量。即使有用的完整证据仍能放下，此时撤回全部事实也会使本已获准的协作无法使用。

## Decision

[范围访问](../../../../packages/collaboration/scope-access/README.zh.md)提供有界在线读取。接收端提出一个正数的 backend 文本额度，并受自身访问配置约束；所有者按该提议与自身上限的较小值计算。独立的版本 3 读取协议保留版本 1、2 的严格解析器，不降级为无接收者预算的响应。邀请、认证 peer、原 capture 关联、到期和撤权仍是独立授权条件。

所有者将实际额度交给当前上下文 backend。完整输出、选中来源、遗漏、provider 比较依据和实际额度仍纳入投影标识及持久记录。接收端在保留投影前拒绝高于提议的返回额度。传输层和原生消费者都不截断文本或改写 backend 的来源归因。

[原生接收](../../../../packages/collaboration/scope-agent-context/README.zh.md)在组合上下文中先为原本地 Task 分配空间。双方来源均有效时，显式配置 `maxLocalContextBytes` 限制本地计算。仅本地接收，以及远端撤回后的本地回退，使用剩余总额度。远端额度等于总额扣除实际本地文本、统一的递送说明和保留的撤回消息。远端读取完成后，同步检查仍是同一本地分配、provider、修订及有效来源区间，才允许准入。本地输入改变需要重新计算；远端失败撤回远端文本，普通本地工作仍可继续。

该分配方式保留个人原有职责，但不假定每条本地发布都比所有共享事实重要。部署配置决定本地上限，backend 在各自额度内选择完整证据。本地未使用的空间可以交给远端输入。无法容纳必需上下文时仍明确失败，不静默扩大额度，也不把组合绑定替换为仅远端输入。

普通文本请求可以使用部分覆盖，并记录预算遗漏。既有当前证据检查仍会在必需信息遗漏时停止自动响应，semantic 的 blocked-current 证据仍然被阻止。容量不增加自动轮次，也不改变已完成响应的比较规则。被动接收失败的文案描述接收不可用，不声称未获授权的自动策略已暂停。

## Alternatives considered

**要求两端配置相同额度。** 独立所有者的 Agent 不必使用相同部署设置，本地上下文大小也会逐次变化。接收者在准入时知道实际可用容量。

**截断过大的返回字符串。** 这可能拆开文件历史，或抹掉失败和撤回证据，却仍保留误导性的投影标识。选择属于 backend，并保留准确覆盖信息。

**先把全部空间交给远端上下文。** 这可能挤掉接收者原有职责。显式本地上限让部署方控制分配，不增加逐条消息的人工工作。

## Consequences

不同配置容量可以传递有界且有用的事实，无需人工选择上下文。这不保证完整覆盖、模型理解，也不保证针对遗漏事实的行动成功。原生消费者要求 peer 支持有界协议；已有持久投影仍按原义读取，不重写任何 Session 代际。

[预算访问测试](../../../../packages/collaboration/scope-access/tests/budget-read.spec.ts)负责提议额度与无效响应；[组合准入测试](../../../../packages/collaboration/scope-agent-context/tests/composite-context.spec.ts)负责本地职责和完整字节计算。正式 profile 的 SDK 及浏览器场景负责实际请求和文件效果证据。跨设备加入、被动接收覆盖展示及真实模型协作质量仍需分别验证。
