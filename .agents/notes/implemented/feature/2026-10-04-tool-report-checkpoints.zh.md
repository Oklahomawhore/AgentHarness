# Agent Note: 完整 Write 报告替代较早的文件证据

Status: implemented

[English](2026-10-04-tool-report-checkpoints.md) | 中文

## Problem

重复的完整 Write 报告会让过时内容继续争夺接收者的上下文预算。逐条选择报告，可能留下较小的旧 Write，却省略较大的替换内容；也可能保留基础 Write，却排除后续 Edit。将全部报告交给语义模型，还会重复发送已经明确被替代的证据。

## Decision

[文本与语义 Task 上下文后端](../../../../packages/collaboration/development-task-context/README.zh.md) 为每个文件选择一个保留的报告片段。成功且内容完整的 Write 开始新片段，同一链中更早的报告标为已被替代。片段包含这条 Write 和所有后续报告，包括 Edit 操作、失败和字段省略。内容完整的空 Write 同样符合条件。失败或不完整的 Write，以及任何 Edit，都不会重置已有片段。序号相同的报告全部保留。

一条链包含贡献授权区间、声明的来源名称与工具集合、根目录索引和精确相对路径。本地贡献与 peer 贡献保持分离。当前 Task 证据和每份继承的冻结快照独立选择；实时替换不能删除继承证据。撤回优先于替代。原始 Task publication 和接收 Session 历史完整保留。

文本提供者按接收者字节预算整段准入每个文件的保留报告。片段放不下时，其中每条报告都记为预算省略；选择不会退回过时的基础内容。语义提供者在推理前移除已被替代的报告，同时保留既有来源记录和输出验证。[接收者后端身份](../architecture/2026-10-02-recipient-task-context-backend.zh.md) 的变化使选择规则改变前的缓存投影失效。

[语义审计恢复](../architecture/2026-10-03-audited-semantic-context.zh.md) 使用保存的请求、捕获的来源和原始回复，不会对较早完成的结果重新应用当前选择规则。改变后端修订不会重置同一审计身份的累计调用预留。[重复报告去除](../bug-fix/2026-10-04-independent-context-delivery.zh.md) 与片段选择保持独立。

## Alternatives considered

**逐条计算报告预算。** 这可能保留旧基础内容，却丢失替换内容或依赖它的 Edit。整段准入保留了这种关联，代价是过大的片段会整体省略。

**只保留最后一条报告。** 最后一条 Edit 可能依赖更早的基础内容，最后一次失败也不能确立新内容。成功且完整的 Write 提供了更窄且明确的替换信号。

**根据 Edit 报告重建当前文件。** 获授权的报告不包含所有可能的外部写入或读取。重建会暗示后端掌握它实际并不知道的文件系统状态。独立的[报告文件提供方](2026-10-07-reported-file-context.zh.md)仅推导明确归因的报告状态，不声称掌握当前磁盘内容。

**让语义模型处理全部重复历史。** 这会为确定性的替换关系消耗输入预算，并让替代判断依赖推理。模型继续负责保留证据的相关性判断和摘要。

## Consequences

接收者得到最新的已报告片段，而非独立验证的当前文件系统快照。来源身份和授权变化会阻止跨链替代。长 Edit 序列和省略元数据仍随保留历史增长；此决策不证明恒定空间、更低账单费用或更好的模型工作结果。

验证覆盖完整和不完整 Write、空内容、失败、授权与快照隔离，以及不可拆分的文本预算。编写的 Session 场景检查实际原生工具写入、接收者模型请求、语义输入替换、撤回、较早证据保留，以及脱离运行时的回放。持久组合验证检查旧审计恢复和跨后端修订的累计调用预留。这些检查不证明在线模型的语义保真或任务改进。
