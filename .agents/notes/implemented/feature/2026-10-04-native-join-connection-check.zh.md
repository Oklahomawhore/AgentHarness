# Agent Note: 在请求文件许可之前验证独立所有者的连接

Status: implemented

[English](2026-10-04-native-join-connection-check.md) | 中文

## Problem

本地有效的协作入口不能证明所有者可连接，也不能证明申请入口仍然开放。要求参与者先选择目录、工具和限额，再发起首次网络请求，会增加地址不可达时的排查成本。用申请本身测试连接，还会产生申请者记录和持久化本地同意。

## Decision

[Scope 访问](../../../../packages/collaboration/scope-access/README.zh.md)提供有界的只读入口预检。认证传输连接入口指定的单个直连地址和固定的所有者身份。所有者核对保存的入口，仅返回可用状态；地址变化不改变原入口身份或权限。操作不占用入口、不使申请过期、不批准或取消申请、不检查 Task 内容，也不保存来源同意。现有请求限额、普通请求容量、销毁和期限规则同样适用。

[原生分享面板](../../../../packages/client/ui-emergence-center/README.zh.md)解析粘贴的入口并在线验证，再展示文件和被动读取许可。入口变化、切换 Session、新建采集或卸载面板会使待完成的 UI 结果失效。参与者分别确认本地采集和联合读取。所有者批准和自动工作同意仍相互独立。地址恢复保留单独的原权限检查。

可用状态只描述一次观察，不预留入口，也不证明之后的可达性、权限或模型采用。提交后，申请操作重新检查权威状态。入口关闭、被占用、过期或无法连接时，结果说明参与者可以采取的操作，不返回其他参与者身份或共享内容。

## Alternatives considered

**提交临时申请。** 这会仅为测试连接而占用单次采集入口并保存同意。预检没有持久化副作用。

**只检查 TCP 或邀请语法。** 可连接的端口可能属于其他服务，编码正确的入口也可能已关闭。预检验证经过认证的所有者及其保存的入口。

**在同一改动中发现多个地址。** 发现、NAT 穿透和候选选择规则需要各自受支持的传输行为。本操作使用明确提供的直连地址，不扫描网络。

## Consequences

参与者在填写本地许可前就能知道连接或入口是否需要修复。无需密钥的浏览器用例检查拒绝握手的 TCP、已关闭入口、在线开放入口及普通获批文件工作，并检查预检期间授权和 Session 记录未改变。它比较浏览器输出，以及真实接收请求与回放 Session 上下文。受控模型回复不证明语义质量或真实设备的接入体验。

流程仍需要配置监听、提供可达地址、交换入口并分别批准。它改善首次连接反馈，不代表开箱即用的互联网连接。[跨设备指南](../../../../docs/user/guide/collaboration-network.zh.md)负责用户步骤。
