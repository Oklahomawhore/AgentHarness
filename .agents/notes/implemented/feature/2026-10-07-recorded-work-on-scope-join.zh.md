# Agent Note: 加入共享范围时分享已记录工作

Status: implemented

[English](2026-10-07-recorded-work-on-scope-join.md) | 中文

## Problem

已有 Agent 可能在其用户加入另一位 owner 的共享目标前就完成相关工作。只采集后续操作会迫使用户重做、复制或解释这些工作，其他 Agent 才能使用。任意回放对话无法证明原文件提供方许可，而本地记录许可也不授权把内容导出。

## Decision

[原生贡献来源](../../../../packages/collaboration/scope-agent-contribution/README.zh.md)接受单独同意，将同一 live Session 当前本地 capture 的记录用于初始化新的远端贡献。原加入表单发现该 capture，并复用文件根目录、工具和额度，无需选择单条消息。同意绑定精确的本地 capture 和 Task assignment epoch；修改拟共享范围会使选择失效。没有合格 capture 时仍可正常加入，但不执行历史初始化。

只有已持久保存的完成 LocalSample 符合资格。原工具参数与完成证据在各自记录的 Session 坐标核对；不会恢复已省略字段。本地 Task receipt 可缺省，未确认记录单独计数。规范根目录身份来自原授权文件提供方观察，而非重新解析旧路径。匹配的根目录可按新许可重新编号。初始化不读取文件、不回放任意对话，也不推断当前文件内容。

来源在启用实时采集前冻结一个有界选择，先为初始化分配远端序号。初始化与实时观察在新 capture 下用相同调用及完成坐标识别一次执行。两者共用 outbox、grant 额度、完整值字节上限和终结处理。激活写入失败时，只要原本地授权仍有效就保留已选计划；重试不会静默挑选更晚的工作。保留记录计入来源容量。激活写入与排队的停止操作在来源队列上确定先后。写入开始前来源失效会阻止初始化；成功冻结后，副本归另行授权的远端 grant 管理。停止本地采集不会撤销该 grant。

明确的第 2 版来源许可授权带有已记录来源摘要的第 2 版报告。普通工具 grant 和第 1 版样本传输拒绝这些报告。实时 Task 准入和继承上下文解析均核对新许可。Owner 标注报告来源，但不独立证明其执行。文本 publication 标明先前尝试及不完整覆盖；语义输出在已接纳引文旁保留历史归属。后续成功且正文完整的 Write 只替代同一授权区间、来源、根目录索引及相对路径中的早期记录。撤回会从当前上下文排除早期报告正文，同时保留带有归属的终结通知。

来源分别提供已选、省略、进行中、未确认和 owner 已确认数量。已选表示保留待传输，已确认表示 owner 已接纳。两者均不证明模型采用或理解。来源不可用会报告初始化失败，后续分享和另行批准的接收仍可用。冷启动结束保留的 capture，不恢复采集或重新选择历史。严格的持久行变体保留现有记录和已提交 Session 代际。

## Alternatives considered

**扫描全部旧工具结果或当前文件。** 工具名称本身不能证明原提供方许可，读取文件也会用新检查替代历史观察。保留的本地 capture 提供更有限且可用的来源。

**要求手工摘要或逐条分享。** 这会重新引入产品要消除的上下文维护工作。一次来源范围选择和明确导出同意适用于有界的已记录工作。

**把本地记录同意当作远端同意。** 接收方与授权不同。发送方必须选择历史导出，owner 必须批准该来源变体。

**使用独立的历史发送器。** 分开的顺序与额度可能使旧报告替代新工作，或超过共享上限。一个冻结 outbox 保留既有贡献序号与撤回规则。

## Consequences

用户保留已有 Agent 和职责，通过常规共享目标入口提供合格的先前工作。能力只覆盖现有有效本地 capture，不提供任意私有历史导入或完整文件快照。截点排除和有界选择可能留下缺口。它不增加自动轮次，也不声称真实模型质量、生产率收益或公网可用性已获证明。

[Task 准入测试](../../../../packages/collaboration/development-task/tests/peer-contribution.spec.ts)覆盖来源许可、不可变归属、精确重试和继承上下文拒绝。[传输测试](../../../../packages/collaboration/scope-access/tests/recorded-contribution.spec.ts)覆盖独立样本协议、上限和终结。[加入表单测试](../../../../packages/client/ui-emergence-center/tests/native-initialization.client.spec.tsx)区分来源同意与交付数量。运行时来源、正式 profile SDK 和浏览器证据由各自消费者包维护。
