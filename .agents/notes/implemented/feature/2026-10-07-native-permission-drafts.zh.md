# Agent Note: 现有原生 Session 的可编辑权限建议

Status: implemented

[English](2026-10-07-native-permission-drafts.md) | 中文

## 问题

用户带着现有 agent（智能体）加入时，项目已经确定，却仍需填写空白的目录、工具和限额表单。要求每个人自行确定运行额度，会增加与共同目标无关的配置工作。填入这些值不能同时授权采集私有工作或启动自主响应。

## 决策

原生贡献服务为选中的运行中普通 Session 提供只读 `permissionDraft`。它使用 Session 记录的目录、当前可见的 Write/Edit 工具和明确的部署配置。缺少目录元数据时返回空根目录选择；未配置默认值时不提供建议。它不读取项目文件或共享上下文、不发送 peer 请求，也不改变 Session 或采集状态。[原生贡献 README](../../../../packages/collaboration/scope-agent-contribution/README.zh.md)定义 API 和配置。

用户在本地或独立所有者的文件权限表单中请求建议。建议值保持可编辑，已有本地采集值优先。应用建议清除表单同意；修改文件范围或限额清除采集和完整内容同意。读取、历史初始化和有限自动工作保留各自明确的授权规则。提交的申请仍通过既有 Host 校验和所有者批准。

迟到的建议不能覆盖后续编辑，也不能跨越 Session、入口、任务分配或采集变化。普通状态刷新不清除草稿。Web profile 管理建议数值，浏览器不自行设定默认值。

## 考虑过的替代方案

**保留空白技术字段。** 这保留了明确选择，但即使 Host 已知项目与部署策略，仍要求每位参与者自行确定配置值。

**填入默认值时自动加入或采集。** 已知项目不代表获准暴露其工作、读取另一所有者的上下文或启动自主执行。建议与这三项决定保持独立。

**从 Host 推断目录或扫描已有工作。** Host 进程目录可能与选中 Session 的项目不同。扫描文件或历史对话会引入与建议权限表单无关的信息访问。

## 影响

首次参与者可以审阅具体项目和有限额度，无需从零填写每个字段。他们仍需选择共同目标并明确授权参与。这改善了原生表单，但不提供网络发现、外部 CLI 自动连接、Claude 空闲推送，也不证明模型协作质量。

验证涵盖运行中 Session 选择、受限工具、缺失配置与项目元数据、不变的权限与 Session 事件、过期响应、编辑值，以及浏览器明确确认后的普通文件工作。冷恢复 fixture（测试前置数据）在关闭前保留已提交的 domain 和 Session 原字节，仅在 dispose（资源释放）后恢复；这些 fixture 输入不是产品备份 API。
