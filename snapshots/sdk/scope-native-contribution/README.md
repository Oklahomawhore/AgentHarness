# Native peer contribution snapshot

English | [中文](README.zh.md)

This reference describes `sdk/scope-native-contribution`. The shipped SDK profile owns an independent source Host, Task owner and receiving Session. Real file tools, durable source records, owner admission and context injection run over authenticated in-process transport. This does not establish physical-device connectivity.

After explicit source consent and owner approval, three real tool operations produce a client correction and a guide. The reported backend reconstructs the client in the first receiving request. A replacement Write followed by a failed Edit retains three complete original peer reports in the second request. The reported backend can encode those reports through observation and grant references; independent expansion compares every original text and grant with the owner’s admitted publications. The third request withdraws all five source records after owner revocation. No recipient recall tool or manual publication is involved.

All actual receiver messages are compared before normalization with complete reconstruction from frozen Session events and flushed persisted events. Python independently expands the raw request representation and compares it with the same admitted reports and normalized TypeScript Session. Committed input and earlier writer generations remain unchanged.

The source performs five real tool calls and seven controlled model requests; the receiver performs three controlled requests. The complete shared frame is limited to 8,000 bytes. These checks establish disclosure, exact representation, supersession and withdrawal; they do not establish real model comprehension or automatic idle collaboration. [Testing](../../../docs/testing.md) owns the supported runners.
