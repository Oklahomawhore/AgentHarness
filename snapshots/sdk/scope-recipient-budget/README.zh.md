# 接收端上下文字节额度快照

[English](README.md) | 中文

本文说明无需密钥的 `sdk/scope-recipient-budget` 场景。正式 SDK profile 创建 B 的 Session；独立 Host 组合创建实际执行的所有者 A Session。双方使用生产工具和持久 Session 存储。认证传输运行于同一进程，不代表跨设备连接验收。

B 已有本地 Task、普通对话历史和可用工具，且没有本地采集。一次联合申请批准读取与文件贡献，自动响应保持关闭。A 对三个独立文件完成真实 Write。其完整投影超过 B 不变的 8,000 字节额度；B 的组合请求为本地 Task 上下文设置最多 4,000 字节，在剩余额度内选择完整的远端文件组。fixture 比较每份选中报告的原文，并要求实际模型请求明确记录预算遗漏。它从实际请求正文测量远端包装开销，核验所有者取得的额度恰好等于 8,000 减去实际本地上下文和完整包装的字节数。随后 B 完成真实 Write，其报告进入 A 的下一次普通请求，无需 recall 或手工复制事实到提示词。

离开会结束 B 的远端订阅和贡献，同时保留原 Task epoch、Session 历史、工具及没有本地采集的状态。规范化之前，每次实际请求中的托管本地和远端上下文均与脱离运行时的 Session 重建结果比较；最终托管上下文还使用已落盘的 header 和事件重建。Python 驱动相同的四轮普通工作，比较 B 完整的规范化 Session 预期及摘要。A 的托管上下文比较限定于每次执行内部；其请求数和字节总量进入摘要，不构成另一份跨次执行的 Session 预期。

`session.v3.jsonl` 提供用户轮次和录制回复；`replay.override.json` 驱动 B 的七次模型请求。A 使用六次受控请求。`workspace.expected/` 独立固定 B 的最终文件内容。不调用付费模型，断言不代表模型质量评估。被动协作 UI 尚未显示每次请求的接收字节或遗漏数量；本场景直接检查持久的模型可见证据。[测试文档](../../../docs/testing.zh.md) 说明快照及 Python smoke 运行器和构建产物要求。
