# Combined native work snapshot

English | [中文](README.zh.md)

This reference describes the keyless `sdk/scope-native-work` scenario. Two original Sessions retain their respective local Tasks, tools, identity, and history. The receiving Session owns the shared Task. The other Session obtains one joint permission to read that Task and contribute explicitly selected file operations, exact command results, and complete final answers. Reading permission remains independent of contribution revocation.

The source executes a real Write, Read, Edit, successful Bash command, and final answer, followed by the same command failing and another final answer. Six samples share one capture, grant, cumulative sequence, and allowance. Read is not collected. The current command replaces its earlier success; both final answers remain separate attributed reports. Owner revocation withdraws all six reports from current context while earlier receiving history remains recorded. The scenario does not require immediate reconciliation of an idle source's remote capture record.

Four actual receiving requests include the initial local Task, both work stages, and revocation, each within 8,000 managed bytes. The fixture compares exact requests with in-memory and flushed Session reconstruction. The raw `.dsh/native-work-audit.json` includes original assignments, source requests and events, durable samples before delivery, command outcomes, complete Task reports, and independently read file content. Private input and pre-permission output do not enter shared context.

The shipped SDK profile runs with controlled provider replies and authenticated in-process transport on one machine. The scenario uses a test filesystem provider that displays `/workspace` paths while preserving real target identities and I/O. It does not measure paid models, physical multi-device delivery, or automatic idle responses. [Testing](../../../docs/testing.md) owns the snapshot and Python runners.
