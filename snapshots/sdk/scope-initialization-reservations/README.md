# Initialization reservation snapshot

English | [中文](README.zh.md)

This reference describes the keyless `sdk/scope-initialization-reservations` scenario. The shipped SDK profile supplies the original receiving Session. Private Host compositions supply the shared Task owner and two original source Sessions. Authenticated in-process transport and controlled provider replies exercise real collection, admission, context projection, and Session persistence on one host.

The source collector retains at most three samples: one local Write record, its independently authorized initialization copy, and another Session's completed answer. A public durable-change barrier releases that answer when the initialization copy commits. Delivery waits for the answer's durable reservation before acknowledging initialization. A fourth completed answer reaches the source Session's history but is refused for sharing. The writer retains its original local Task assignment. The receiving Session retains its identity, header, tools, and history; it has no prior local Task assignment in this scenario.

Three actual provider requests cover the original receiving Session, admission of both permitted sources, and precise withdrawal of the initialized copy while the independent answer remains. Complete framed context stays within 8,000 bytes. In-memory and on-disk Session reconstruction reproduce the exact requests. Raw source logs, admission receipts, original execution digests, and independently read file contents establish provenance. Owner revocation withdraws the receiving context; an idle source may retain its remote capture record until subsequent work or expiry, while its separately authorized local capture remains unchanged. This scenario does not assert immediate source shutdown.

`session.v3.jsonl` supplies the turns and recorded replies; the fixture executes the real Write. A test filesystem provider keeps real target identities and I/O while presenting stable `/workspace` paths in this scenario, so execution digests remain comparable across temporary directories. Python drives the same composition and compares the complete Session oracle and independently derived audit summary. This controlled scenario makes no claim about external CLI attachment, physical multi-host delivery, autonomous response quality, or paid models.
