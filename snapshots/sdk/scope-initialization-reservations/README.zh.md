# 初始化保留额度快照

[English](README.md) | 中文

本参考文档描述无密钥的 `sdk/scope-initialization-reservations` 场景。随产品提供的 SDK profile 提供原有接收 Session。私有 Host 组合提供共享 Task 所有者和两个原有来源 Session。经过认证的进程内传输与受控 provider 回复在同一主机上运行真实采集、准入、上下文投影和 Session 持久化。

来源采集器最多保留三个样本：一份本地 Write 记录、经过独立授权的初始化副本，以及另一个 Session 的完整答复。公开的持久化变更屏障在初始化副本提交时放行该答复。传输会等到答复额度真正落盘后才确认初始化。第四份完整答复进入来源 Session 历史，但被拒绝分享。写入方保留原有本地 Task 归属。接收 Session 保留身份、头信息、工具和历史；本场景中的接收方事先没有本地 Task 归属。

三个真实 provider 请求覆盖原有接收 Session、两个获准来源的准入，以及精确撤回初始化副本并保留独立答复。包含完整封装的上下文不超过 8,000 字节。内存与磁盘 Session 重建均复现完全一致的请求。原始来源日志、准入回执、原始执行摘要和独立读取的文件内容确定信息来源。所有者撤销授权后，接收上下文移除对应内容；空闲来源可能保留远端采集记录，直到后续工作或到期；其独立授权的本地采集保持不变。本场景不声称来源立即停止。

`session.v3.jsonl` 提供回合和记录的回复；fixture 执行真实 Write。测试文件系统 provider 保留真实目标身份和 I/O，仅在本场景中展示稳定的 `/workspace` 路径，使不同临时目录中的执行摘要仍可比对。Python 驱动相同组合，比对完整 Session 预期和独立推导的审计摘要。本受控场景不证明外部 CLI 接入、物理多主机交付、自主响应质量或付费模型表现。[测试文档](../../../docs/testing.zh.md)定义快照与 Python scope 运行器及其构建产物要求。
