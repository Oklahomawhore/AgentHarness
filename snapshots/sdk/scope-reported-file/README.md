This reference describes the keyless `sdk/scope-reported-file` scenario. The shipped `dsh --profile sdk` starts the receiver; its owned overlay creates an independent source Host with production native tools and durable storage. The two Hosts use authenticated in-process transport, not separate application processes or physical devices.

One explicitly authorized local capture performs two real Writes and four real Edits across an implementation and a companion file. The receiver first records the implementation’s original Write and the reconstructed companion, then both complete `reported-files` results. Their dependencies contain four and two operations, with exact authority, file identity, ordered dependency digests and warnings that reports do not verify current files. Stopping the exact capture removes both derived files and marks all six sources withdrawn. Original files and Session history remain.

Each actual receiver request is compared before normalization with complete messages reconstructed from frozen memory and flushed Session headers and events. Independent expansion restores complete grant values shared by both reconstructed records. Python repeats the three turns, compares its normalized Session with the TypeScript recording, and checks raw request bytes, contents, dependency digests and withdrawal. Both source files are compared with `source-workspace.expected/`. Separate writer expectations preserve every committed generation.

The source makes eight controlled requests and the receiver makes three. No paid model is called; scripted prose does not establish model understanding. This scene checks persisted representation and provenance, not long history capacity, edits without an authorized Write or private-file disclosure. The complete shared frame remains within 8,000 bytes. [Testing](../../../docs/testing.md) owns the snapshot and Python runners and their built-artifact requirements.
