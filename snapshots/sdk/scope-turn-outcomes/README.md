# Completed final-answer contribution snapshot

English | [中文](README.zh.md)

This reference describes `sdk/scope-turn-outcomes`. The shipped SDK profile starts the receiver; private Loader compositions start an independent owner and source. The source has no Session working directory, filesystem service or registered file tools. Only model responses are scripted. In-process authenticated transport does not establish operation across physical devices.

The original source Session completes a private answer before consent, then receives explicit final-answer sharing permission. Its next two ordinary user-channel turns produce separate complete answers, including one response with private reasoning. The three receiver turns observe the first answer, both independent answers, and exact contribution revocation. No per-update publish or recall tool is called. Raw private prompts, reasoning and pre-consent answers remain source-local; a final answer may still quote input content under its disclosure permission.

Before each sample leaves, the fixture reads the source Session file and checks complete durable evidence. Each receiving request is reconstructed from both frozen events and the physical Session file before normalization. Python repeats the three turns and independently checks source text digests, original capture attribution, exact wire events, preserved history and current withdrawal. Every complete shared frame stays within 8,000 bytes.

This scene verifies automatic collection and delivery of permitted non-code reports. It does not verify the reports as facts, infer that later answers supersede earlier ones, establish model comprehension, or authorize automatic execution. The source lifecycle tests own failed, steered, oversized and restored-turn exclusions. [Testing](../../../docs/testing.md) owns the snapshot runner and built-artifact requirements.
