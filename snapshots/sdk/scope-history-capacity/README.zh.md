# 长 scope 历史快照

[English](README.md) | 中文

本参考说明无需密钥的 `sdk/scope-history-capacity` 场景。正式 SDK profile 拥有接收 Session。两个独立 Loader Host 分别拥有 Task 和使用生产文件系统工具的来源 Session。经过身份认证的传输运行在同一进程内；本场景不证明跨设备连接。

fixture 通过 ScopeAccess 提交 500 条已获授权的合成完整文件 Write 报告。每条报告都有不同的哈希标识，并替代同一文件的旧报告。随后来源 Agent 执行两次真实 Write 工具，每次再完成一次受控回复。fixture 核对各次工具结果、落盘文件和已刷盘 Session 日志后，通过同一贡献 API 提交对应报告。这些提交由 fixture 驱动；本场景不验证自动采集，也不声称执行了 500 次真实工具调用。

接收方的两次普通请求分别包含最新报告和更正，无需 recall 工具，也不通过用户提示传递事实。各次解码投影按原顺序完整保留此前所有 publication 引用，并明确标为 superseded 省略。当前请求不含旧文件正文。fixture 测量实际完整编码读取响应小于 60,000 字节，而等价未压缩响应超过该上限；解码仍限于 2 MiB。托管请求上下文不超过 8,000 字节。传输观测覆盖响应 JSON，不代表物理网络帧。

两次接收请求均在规范化前与内存事件及已刷盘磁盘事件的完整离线重建结果比较。更正后，早先采用的上下文仍保留于持久历史。来源执行四次受控模型请求和两次真实文件写入；接收方执行两次录制请求。场景不调用付费模型，回放也不证明模型质量。[测试文档](../../../docs/testing.zh.md) 负责正式 profile 快照运行器及构建产物要求。
