# 跨设备连接协作

[English](collaboration-network.md) | 中文

当两个人各自运行独立的 AgentHarness Host，希望围绕其中一人的 Task 协作时，使用本指南。每个人保留自己的 Host 和浏览器会话。对方必须能够通过 IP 地址和 TCP 端口直接访问所有者；目前没有互联网自动发现、NAT 穿透或中继服务。

## 1. 配置所有者的监听

1. 在所有者的本机浏览器页面打开**设置 → 插件 → 协作网络**。远程浏览器不能保存这项 Host 设置。
2. 选择允许其他设备连接的选项，填写 1 至 65535 之间可用的 TCP 端口。这会监听全部 IPv4 网卡。如果双方都在这台电脑上运行，保留**仅运行 AgentHarness 的设备**。
3. 保存。确认文案表示设置已存储；当前监听保持不变。
4. 使用相同的 Harness home 停止并启动 Host。对于已安装的服务，先运行 `agentharness stop`，再运行 `agentharness start`。回到协作中心并刷新地址。

浏览器自身的端口和 `--host` 选项配置另一项监听。独立 Agent 加入 Task 无需分享浏览器管理 URL。协作监听本身不会创建读取授权或文件共享权限。

## 2. 选择地址并邀请

1. 选中所有者的独立 Task，打开其独立设备协作控件和文件贡献权限。
2. 在**邀请使用的本机地址**中选择另一台设备能够访问的地址。只能选择 Host 当前公布的地址。回环地址仅适用于本机；网卡地址只是候选，不能证明可达。存在多张网卡或 VPN 时，选择适合对方设备的路由。
3. 生成邀请一个 Session 加入的入口，将入口交给另一人。对方使用项目工作区中已运行的普通原生 Session，且该 Session 尚未连接本地 Task 或远端读取，在其中打开**协作**，展开文件分享，粘贴并核对入口，分别确认 Task 读取与文件采集许可，选择已有目录和写入、编辑操作，设置限额并提交申请。开始由模型驱动的文件工作前需要配置可用模型；发送模型请求本身不是准入协议的前置要求。
4. 在所有者页面审核申请人和限额，填写其职责并批准。后台准入会连接被动读取和已许可的文件观察；启动自动工作需要另外明确授权。

如果所有者自己的 Agent 也要参与，在其原生 Session 中选择这个本地 Task，并单独许可文件分享。仅创建 Task 不会连接所有者的 Agent，也不会共享其文件。

职责用于选择上下文，不会隐藏该 Task 中其他已共享内容。私有工作应放在另一个未共享的 Task。每项权限和投递都有自己的状态；批准本身不能证明 Agent 已使用上下文。

## 3. 恢复连接

如果另一方的 Host 无法连接，检查所选 IP、TCP 端口、防火墙和路由。设置已保存、地址已列出以及同机连接成功，都不能证明第二台电脑能够访问。系统不会尝试中继回退。

所有者保留 Harness home、已存储的 Task 数据和设备身份而仅改变地址时，刷新所有者控件并选择当前地址。恢复原入口，然后在参与者的原 Session 中打开 **协作 → 分享本会话的文件工作 → 更新所有者连接地址**，粘贴恢复内容、核对并保存恢复地址。Host 保留原权限、限制、待发样本和已开始的撤回。联合入口还会在显示时的读取状态仍匹配时恢复原读取。

独立只读连接可在接收详情下展开 **更新所有者连接地址**，输入所有者的新地址。原订阅与自动协作额度保留，包括已消耗的启动次数。后续本地暂停、离开或替换操作可能使较早的恢复操作失效；请刷新并核对当前状态。已结束或过期的权限仍保持结束。保存地址不证明可达或上下文已送达。所有者丢失原身份或 Task 数据时，修改地址无法恢复它们。

如果所选端口被占用导致重启失败，停止 Host，仅修改其 `settings.yaml` 中的 `scope-network.listenAddresses`，改为可用的固定 IP/TCP 监听，或使用 `/ip4/127.0.0.1/tcp/0` 恢复仅本机模式，然后重新启动。保留其他设置。用户设置优先于组合配置，包括 `AGENTHARNESS_SCOPE_LISTEN`；修改该环境变量不会覆盖已保存的设置。自定义 IPv6 和多地址值会继续显示在卡片中，只有明确改成卡片支持的模式时才会被替换。

[Scope transport](../../../packages/collaboration/scope-transport/README.zh.md) 定义监听校验和网络限制。[使用 AgentHarness](index.zh.md) 介绍本机启动及独立的受信集群选项。
