# 跨设备连接协作

[English](collaboration-network.md) | 中文

当多个人各自运行独立的 AgentHarness Host，希望围绕其中一人的 Task 协作时，使用本指南。每个人保留自己的 Host 和浏览器会话。对方必须能够通过 IP 地址和 TCP 端口直接访问所有者；目前没有互联网自动发现、NAT 穿透或中继服务。

## 1. 配置所有者的监听

1. 在所有者的本机浏览器页面打开**设置 → 插件 → 协作网络**。远程浏览器不能保存这项 Host 设置。
2. 选择允许其他设备连接的选项，填写 1 至 65535 之间可用的 TCP 端口。这会监听全部 IPv4 网卡。如果双方都在这台电脑上运行，保留**仅运行 AgentHarness 的设备**。
3. 保存。确认文案表示设置已存储；当前监听保持不变。
4. 使用相同的 Harness home 停止并启动 Host。对于已安装的服务，先运行 `agentharness stop`，再运行 `agentharness start`。回到协作中心并刷新地址。

浏览器自身的端口和 `--host` 选项配置另一项监听。独立 Agent 加入 Task 无需分享浏览器管理 URL。协作监听本身不会创建读取授权或文件共享权限。

## 2. 选择地址并邀请

1. 选中所有者的独立 Task，打开其独立设备协作控件和文件贡献权限。
2. 在**邀请使用的本机地址**中选择另一台设备能够访问的地址。只能选择 Host 当前公布的地址。回环地址仅适用于本机；网卡地址只是候选，不能证明可达。存在多张网卡或 VPN 时，选择适合对方设备的路由。
3. 生成邀请一个 Session 加入的入口；多人协作时选择**邀请多人加入同一目标**，设置**累计申请名额**，将同一个多人入口交给各位参与者。对方使用项目工作区中已运行的普通原生 Session，且该 Session 尚未连接远端读取；已有本地 Task 保持分配，在其中打开**协作**，展开文件分享，粘贴入口并选择**验证连接**；所有者确认入口可用后才显示文件权限表单，分别确认 Task 读取与文件采集许可，选择已有目录和写入、编辑操作，设置限额并提交申请。开始由模型驱动的文件工作前需要配置可用模型；发送模型请求本身不是准入协议的前置要求。
4. 参与者还可在同一申请中选择有限自动工作，明确填写本地目标、额外启动次数、每轮步数和最短间隔；即使 Session 已有本地自动策略，该选项也初始关闭。加入时确认原本地 Task；加入后的 Agent 保留历史、工具和独立授权的本地文件分享。在所有者页面审核申请人和限额，填写其职责并批准读取与贡献。后台准入会连接原 Session 及其在本机保存的自动许可；所有者不选择其执行目标或额度。没有这项独立本地许可时，接收保持被动。

已有 Claude 主会话可以使用同一个联合或多人入口。通过 [Claude scope 控件](../../../packages/collaboration/claude-scope/README.zh.md)配置项目 hooks，再选中已观察的会话。选择**粘贴协作申请入口**，粘贴入口并选择**核对申请入口**。选择目录、Write/Edit 操作与限额，分别同意被动接收与文件采集，再选择**申请加入并在批准后连接**。所有者批准后，后台会连接两项权限，页面关闭也不影响。无需第二份接收邀请，也不包含 Claude 自动执行许可。已有的不兼容本地 Task 或读取选择必须显式处理。**停止贡献**会保留已采用的读取、取消尚未采用的读取；**退出此次协作**停止原联合权限。

多人入口中的每位申请者都有独立决定与权限。拒绝、取消和到期的申请仍占用名额；Host 的总容量和记录大小也可能限制准入。**关闭新申请入口**只停止新申请，不撤销现有授权；待审批申请仍可在入口到期前批准。选择**结束该成员协作**，可同时撤销其读取与贡献；也可单独管理各项权限。另一成员离开不会终止其余权限。离开读取连接会停止本地接收；所有者可用**结束该成员协作**撤销保留的读取授权。

自动采用前更换原 Agent 或接收服务，会取消待采用许可。恢复后的自动绑定保持暂停。采用后停止文件分享会保留读取及其自动许可；可在读取面板暂停自动工作或离开连接。

连接验证使用入口中的所有者设备身份，不提交申请、读取共享内容或启用采集。无法连接时，需确认地址可达且 Host 正在运行；入口已关闭、被占用或过期时，需获取新入口。验证成功不会预留入口、授予权限或确认上下文已送达；所有者仍在收到申请时重新检查。

如果所有者自己的 Agent 也要参与，在其原生 Session 中选择这个本地 Task，并单独许可文件分享。仅创建 Task 不会连接所有者的 Agent，也不会共享其文件。

已经分配到自己本地 Task 的 Agent，也可以通过文件贡献入口，单独向另一个所有者分享文件工作。选择远端分享页，验证该入口，并批准其目录、工具和限额。现有本地采集保持独立，各个目标在各自面板中停止。这项仅文件许可不会启用远端读取或改变本地目标。上述联合流程另行接通读取并保留该本地 Task。离开远端连接后，原本地自动策略恢复为暂停，全部已消耗启动次数保留；本地文件分享保持独立。

职责用于选择上下文，不会隐藏该 Task 中其他已共享内容。私有工作应放在另一个未共享的 Task。每项权限和投递都有自己的状态；批准本身不能证明 Agent 已使用上下文。

## 3. 恢复连接

如果另一方的 Host 无法连接，检查所选 IP、TCP 端口、防火墙和路由。设置已保存、地址已列出以及同机连接成功，都不能证明第二台电脑能够访问。系统不会尝试中继回退。

所有者保留 Harness home、已存储的 Task 数据和设备身份而仅改变地址时，刷新所有者控件并选择当前地址。恢复原入口，然后在参与者的原 Session 中打开 **协作 → 分享本会话的文件工作 → 更新所有者连接地址**，粘贴恢复内容、核对并保存恢复地址。Host 保留原权限、限制、待发样本和已开始的撤回。联合入口还会在显示时的读取状态仍匹配时恢复原读取。

Claude 联合入口在原来已观察的会话中打开**此次协作的共享上下文 → 更新所有者连接地址**，输入所有者的新地址，选择**保存恢复地址**。待审批时，以及贡献停止但读取保留时，也可使用该操作。它保留原联合权限，不会替换后续手工读取选择。

独立只读连接可在接收详情下展开 **更新所有者连接地址**，输入所有者的新地址。原订阅与自动协作额度保留，包括已消耗的启动次数。后续本地暂停、离开或替换操作可能使较早的恢复操作失效；请刷新并核对当前状态。已结束或过期的权限仍保持结束。保存地址不证明可达或上下文已送达。所有者丢失原身份或 Task 数据时，修改地址无法恢复它们。

如果所选端口被占用导致重启失败，停止 Host，仅修改其 `settings.yaml` 中的 `scope-network.listenAddresses`，改为可用的固定 IP/TCP 监听，或使用 `/ip4/127.0.0.1/tcp/0` 恢复仅本机模式，然后重新启动。保留其他设置。用户设置优先于组合配置，包括 `AGENTHARNESS_SCOPE_LISTEN`；修改该环境变量不会覆盖已保存的设置。自定义 IPv6 和多地址值会继续显示在卡片中，只有明确改成卡片支持的模式时才会被替换。

[Scope transport](../../../packages/collaboration/scope-transport/README.zh.md) 定义监听校验和网络限制。[使用 AgentHarness](index.zh.md) 介绍本机启动及独立的受信集群选项。
